# Antigravity 문서 협업 워크플로우

## 1. 시작

새 대화에서는 먼저 다음 파일을 멘션합니다.

```text
@PROJECT_CONTEXT.md
@DOCUMENT_RULES.md
@SPEC_WRITING_GUIDE.md
```

## 2. 문서 생성

```text
@Templates/TEMPLATE_기획_명세서.md 양식으로
에르고스퀘어 전개 시스템 명세서를 작성해줘.
저장 위치는 ErgoSquare_Document/02_개발_전달용/P0_기획_명세서/야.
확정되지 않은 내용에는 TBD를 표시하고 초안 배너를 유지해.
```

## 3. 검수와 승격

```text
아이디어
→ 03_기획_부록_참고문서
→ 기획 초안
→ 검토 요청
→ 기획자 승인
→ 01_SSOT_최종_기준문서 또는 02_개발_전달용
→ 구현·QA
→ 변경 시 이전 확정본 Archive
```

AI는 문서를 작성할 수 있지만 확정 배너는 기획자의 명시적 승인 없이 제거하지 않습니다.

## 4. 개발일지

```text
@Templates/TEMPLATE_개발일지.md 양식으로 오늘 개발일지를 작성해줘.
완료한 작업, 수정 파일, 검증 결과, 다음 작업을 포함하고
ErgoSquare_Document/05_개인_개발일지/개발일지/에 저장해.
```

## 5. 트러블슈팅

```text
@Templates/TEMPLATE_트러블슈팅.md 양식으로
발생 조건, 실패 가설, 실제 원인, 수정 내용, 재현 검증을 정리해줘.
기획 문제와 구현 문제를 구분해.
```

## 6. 주간 문서 감사

매주 한 번 아래 작업을 수행합니다.

1. SSOT와 개발 전달 문서의 충돌 확인
2. 구현 완료 표기에 증거가 연결되어 있는지 확인
3. 미확정 `TBD` 목록 정리
4. 오래된 문서를 아카이브 후보로 표시
5. README 문서 인벤토리 갱신

## 7. Unity 연동 시

- 기본 접근은 읽기 전용입니다.
- 문서 저장소 요청으로 게임 소스 코드를 수정하지 않습니다.
- 코드가 현재 구현의 근거라면 파일과 클래스명을 기록합니다.
- 기획과 구현이 다르면 덮어쓰지 말고 차이를 표로 남깁니다.

## 8. Git 작업

- 문서 단위로 작은 커밋을 유지합니다.
- 확정 문서 변경은 변경 이유를 커밋 메시지에 포함합니다.
- 이미지·영상 추가 전 용량을 확인합니다.
- `main`에는 검토된 문서만 병합하는 것을 권장합니다.
