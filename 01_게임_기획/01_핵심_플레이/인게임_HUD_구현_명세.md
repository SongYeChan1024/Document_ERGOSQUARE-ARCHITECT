## 기준 시안

![튜토리얼 동굴 인게임 HUD 기준 시안](../../07_에셋/이미지/UI_UX/튜토리얼_동굴_인게임_HUD_기준시안_v1.png)

시안은 로스트아크 계열 PC 액션 RPG의 정보 계층을 참고하되, 마름모 격자·청록색 코어 에너지·절제된 금색 프레임으로 에르고스퀘어만의 시각 언어를 구성합니다. 특정 게임의 그래픽 자산과 장식을 그대로 복제하지 않습니다.

## 화면 정보 계층

| 위치 | 표시 정보 | 구현 원칙 |
| --- | --- | --- |
| 좌측 상단 | 현재 목표, 게이트 위험 경고 | 한 번에 하나의 핵심 목표만 강조 |
| 우측 상단 | 미니맵, 게이트 불안정도와 제한 시간 | 탐색과 철수 판단을 함께 지원 |
| 중앙 하단 | 체력, 코어 에너지, `QWERASDF`, `1~4` | 전투 중 가장 자주 확인하는 정보 통합 |
| 우측 하단 | `Space`, `G`, `B`, `Tab` 상황 안내 | 키와 행동명을 함께 표시 |
| 월드 공간 | 코어·가방 내구도, 상호작용 프롬프트 | 대상과 상태의 관계를 화면 좌표로 전달 |

## 정신 집중 표시 규칙

- 정신 집중은 별도 자원이나 게이지가 아닙니다.
- `Space`를 누르고 있는 동안 기존 코어 에너지 바가 회복되는 애니메이션만 표시합니다.
- `Space / 정신 집중`은 조작 안내이며 진행도·충전량·재사용 대기 게이지를 포함하지 않습니다.
- 플레이어가 기능을 익힌 뒤에는 안전 구간이나 자원 부족 상황에서만 안내를 다시 노출합니다.

## 격자와 파츠 표시 규칙

- 코어와 가방은 각각 하나의 아이소메트릭 셀 중앙에 스냅합니다.
- 메시의 바닥 투영 영역 전체가 셀 경계를 넘지 않아야 합니다.
- 월드 내구도 표시는 파츠 상단에 고정하며 카메라와의 거리에 따라 최소 크기를 보장합니다.
- 격자는 상시 강하게 표시하지 않고 전개·피격·선택 상태에서 명도를 높입니다.

## 에셋화 원칙

| 구분 | 이미지 에셋 | Unity에서 조립할 요소 |
| --- | --- | --- |
| 상태 바 | 빈 외곽 프레임, 장식 캡 | 게이지 채움, 수치, 피해·회복 애니메이션 |
| 슬롯 | 기본 슬롯 프레임, 선택·위험 오버레이 | 스킬 아이콘, 키, 비용, 재사용 대기 |
| 조작 안내 | 키캡 프레임 | 현재 바인딩과 한글 행동명 |
| 임무 패널 | 반투명 패널과 경고 장식 | 목표 문장, 단계, 제한 시간 |
| 월드 상태 | 코어·가방 상태 프레임 | 대상명, 내구도, 파괴 경고 |

한글, 키 바인딩, 숫자와 게이지 채움은 이미지에 굽지 않습니다. Unity의 텍스트와 UI 컴포넌트로 표시해 해상도·입력 장치·현지화 변경에 대응합니다. 크기가 변하는 프레임은 `9-Slice Sprite`로 사용합니다.

## 튜토리얼 비주얼 기준

- 플레이어는 아르바이트를 마치고 귀가하다 흡인된 현대 민간인이므로 후드·재킷·바지·운동화의 평상복을 착용합니다.
- 흡인과 탈출 흔적은 먼지, 가벼운 찢김과 작은 상처로 표현하며 전문 전투복이나 판금 갑옷은 사용하지 않습니다.
- 게이트 내부는 습하고 폐쇄적인 동굴을 기본 환경으로 사용합니다.
- 최종 목적지는 동굴 안에 비정상적으로 재현된 초가집이며, 월도를 든 거대한 병사형 도깨비가 이를 지킵니다.
- 초가집은 편안한 마을이 아니라 이면이 인간의 기억을 불완전하게 모방한 이질적인 랜드마크로 연출합니다.

## 프로토타입 구현 순서

1. 해상도에 대응하는 HUD 앵커와 안전 영역을 구성합니다.
2. 체력·코어 에너지 바를 실제 런타임 값에 연결합니다.
3. `QWERASDF`, `1~4`, `Space`, `G`, `B`, `Tab` 슬롯을 데이터 기반으로 생성합니다.
4. 코어와 가방의 월드 내구도 UI를 월드 좌표 추적 방식으로 구현합니다.
5. 기준 시안에서 분리한 프레임·아이콘 에셋을 임시 UI에 교체 적용합니다.
6. 16:9, 16:10과 울트라와이드에서 중앙 전투 시야가 가려지지 않는지 검증합니다.

## 현재 Unity 프로토타입

| 구성 | 프로젝트 경로 | 역할 |
| --- | --- | --- |
| HUD 구조 | `03.Prefabs/Presentation/UI/HUD_Canvas_Prototype.prefab` | Canvas 아래에 목표·불안정도·상태 바·슬롯·조작 안내 배치 |
| 해상도 대응 | 프리팹의 `Canvas Scaler`와 각 `RectTransform` | 1920×1080 기준, `Scale With Screen Size`, 가로·세로 보간 0.5, 영역별 앵커 사용 |
| 런타임 연결 | `02.Scripts/Presentation/Runtime/UI/CanvasHudPresenter.cs` | 코어 자원 이벤트를 기존 코어 에너지 바와 수치에 연결 |
| 에디터 조립 | `02.Scripts/Editor/PrototypeCanvasHudSceneBuilder.cs` | Sprite 설정·9-Slice·프리팹 생성과 TestMap 연결 |
| 공통 프레임 | `04.Graphics/Common/Textures/UI/HUD/` | 슬롯·상태 바·키캡·목표 패널 투명 이미지 |

Unity 메뉴 `Tools > ERGOSQUARE > Prototype > Build Canvas In-game HUD`를 다시 실행하면 같은 이름의 HUD를 중복 생성하지 않고 Sprite 설정, 참조와 프리팹을 갱신합니다. 이전 UI Toolkit 파일과 `HUD_Prototype.prefab`은 비교·참고용으로 보존하지만 `TestMap`의 활성 HUD로 사용하지 않습니다.

### 해상도 대응 규칙

- Canvas는 `Screen Space - Overlay`를 사용합니다.
- 기준 해상도는 1920×1080이고 `Canvas Scaler`의 `Match` 값은 0.5입니다.
- 임무는 좌측 상단, 미니맵은 우측 상단, 전투 슬롯은 하단 중앙 앵커에 고정합니다.
- 반복 슬롯은 `Horizontal Layout Group`으로 정렬해 해상도가 바뀌어도 순서를 유지합니다.
- 크기가 달라지는 상태 바와 패널은 9-Slice Sprite로 늘려 테두리 두께를 보존합니다.
- 현재 프로토타입은 Full HD 16:9와 16:10 Game View에서 위치 유지와 겹침 여부를 확인했습니다. 울트라와이드와 안전 영역은 후속 검증 대상입니다.
