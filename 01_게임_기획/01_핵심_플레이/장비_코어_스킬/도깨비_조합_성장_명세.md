# 도깨비 조합과 성장 명세

> 문서 상태: 초안 및 플레이테스트용 프로토타입. 작성자: 송예찬. 수정일: 2026-10-08.
> 빗자루 1·2·3자루 조합의 공격 횟수와 기존 개체 유지 방향은 합의된 규칙입니다. 수치는 첫 플레이테스트 가안이며 엑셀에서 변경합니다.

## 목적

파밍으로 얻은 같은 물건을 조합하면 동행하던 도깨비의 스킬 동작이 확장됩니다. 3단계 이후에는 피해·쿨타임·소모 자원을 강화하고, 이후 다른 물건의 재료로 새로운 형태에 분기하더라도 같은 도깨비와의 관계를 유지합니다. 도깨비 세 개를 청사진에 동시에 배치하는 규칙과 구분합니다.

이번 구현은 빗자루 근접형의 조합·수치 강화·연계 전투와 엑셀 데이터 연결을 대상으로 합니다. 월도 조각 분기, 유대에 따른 외형·장정형 성장, 정식 제작 시설과 드롭 경제는 후속 범위입니다.

## 사용자 흐름

1. 첫 빗자루를 획득하면 고유 ID를 가진 동행 개체가 생깁니다.
2. Tab의 청사진 편집에서 빗자루를 배치하고 원하는 스킬 키에 할당합니다. Q는 설명용 기본 예시이며 QWERASDF 재할당은 유지합니다.
3. 추가로 얻은 빗자루는 조합 재료 수량으로 보관합니다. 동행 개체를 교체하거나 자동 조합하지 않습니다.
4. 편집 화면에서 빗자루를 선택하고 조합 버튼을 누릅니다. 기존 개체와 유대 유지 안내를 확인한 뒤 한 번 더 눌러 확정합니다.
5. 2단계에는 좌우 쓸기, 3단계에는 자루 찌르기까지 연계할 수 있습니다.
6. 3단계 이후 같은 재료를 피해·쿨타임·자원 효율 강화 중 하나에 사용합니다.

## 동작 규칙

### 개체와 재료

| 대상 | 소유 데이터 | 조합 결과 |
| --- | --- | --- |
| 동행 도깨비 | `InstanceId`, 원본 파츠, 추첨 능력치, 현재 내구도, 성장 상태 | 동일 객체를 유지하며 조합 단계만 증가 |
| 빗자루 재료 | `BROOM_COPY` 수량 | 레시피에 정한 개수만 차감 |
| 별도 유대 개체 | 별도 고유 ID와 유대 기록 | 자동 재료화 금지. 현재 제작 API는 입력으로 받지 않음 |
| 월도 조각 | `WOLDO_FRAGMENT` 후보 | 후속 분기용. 현재 월도 도깨비 보상과 다른 재료 |

현재 단일 보유 프로토타입은 추가 빗자루 획득을 **유대가 없는 물건 재료**로 취급합니다. 향후 여러 도깨비를 보유하게 되면 개체 보관함과 재료 보관함을 구분하고, 개체를 재료로 선택하는 별도 확인 흐름이 필요합니다. 유대가 있는 개체를 경고 없이 카운터로 바꾸면 안 됩니다.

조합은 재료·단계·파손 상태를 모두 확인한 뒤 수량 차감과 단계 증가를 한 번에 수행합니다. 실패하면 어떠한 값도 바꾸지 않습니다. 공격력 추첨, 이름, 내구도와 배치를 새로 생성하지 않으며 조합으로 무료 수리하지 않습니다. 이번 가안에서 청사진 점유는 기존 1×1을 유지합니다.

### 빗자루 단계별 공격

| 조합 단계 | 입력 | 동작 | 쿨타임 가안 | 연계 유예 |
| --- | --- | --- | --- | --- |
| 1자루 | Q | 짧게 돌진하며 왼쪽 쓸기 | 4.5초 | 단발 종료 |
| 2자루 | Q → Q | 왼쪽 쓸기 → 오른쪽 쓸기 | 5.5초 | 각 타 종료 후 1.2초 |
| 3자루 | Q → Q → Q | 왼쪽 쓸기 → 오른쪽 쓸기 → 자루 찌르기 | 6.5초 | 각 타 종료 후 1.2초 |

왼쪽과 오른쪽은 **캐릭터의 진행 방향 기준**입니다. 화면의 좌우와 일치하지 않을 수 있습니다. 각 타는 입력 시 커서 방향을 읽어 방향을 정하고, 승인된 타의 도중에는 그 방향으로 돌진합니다. 다음 입력에서 방향을 바꿀 수 있습니다.

- 쿨타임은 첫 타 승인 시부터 시작합니다. 연계 중 다음 타는 쿨타임과 무관하게 사용할 수 있지만 새 1타는 사용할 수 없습니다.
- 키 재할당으로 쿨타임을 회피하지 못하도록 고유 개체 ID로 쿨타임을 관리합니다.
- 타마다 필요한 자원을 따로 소비합니다. 3타 전체 비용을 첫 타에서 미리 차감하지 않습니다.
- 모션 마지막 0.18초의 같은 개체 입력 하나를 예약할 수 있습니다. 이른 입력은 무시하며 여러 입력을 무한히 적재하지 않습니다.
- 유예가 지나면 다음 순서를 1타로 되돌립니다. 진행 중인 공유 쿨타임은 유지합니다.
- 메뉴가 열림, 기본 공격 회복 중, 파손, 자원 계통 비활성, 자원 부족이면 승인하지 않습니다. 실패한 입력은 피해·돌진·자원 소비를 발생시키지 않습니다.
- 스킬 도중 파츠가 파손되면 접촉 피해와 후속 연계를 중단합니다. 이미 승인된 자원은 환불하지 않습니다.
- 컨트롤러가 비활성화되면 실행과 예약을 취소하고 이동 차단을 해제합니다. 안전 구역의 기존 전투 차단 정책을 유지합니다.

### 공격 수치 가안

| 공격 | 기본 피해 | 공격력 계수 | 정기 | 돌진 | 모션 | 경직 | 밀림 | 넘어짐 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 왼쪽 쓸기 | 8 | 0.85 | 18 | 1.4m | 0.45초 | 0.25초 | 0.55m | 없음 |
| 오른쪽 쓸기 | 9 | 1.00 | 18 | 1.6m | 0.48초 | 0.30초 | 0.75m | 없음 |
| 자루 찌르기 | 12 | 1.25 | 24 | 2.0m | 0.55초 | 0.40초 | 1.25m | 0.45초 |

```text
피해 = (기본 피해 + 파츠의 추첨 공격력 × 공격력 계수) × 피해 강화 배율
타별 자원 비용 = Actions.resourceCost × 자원 효율 배율
공유 쿨타임 = Stages.cooldown × 쿨타임 강화 배율
실제 모션 시간 = Actions.duration / 파츠 공격 속도
접촉 시점 = 실제 모션 시간 × Actions.impactRatio
```

공격력이 10이고 강화가 없다면 각 타는 16.5 / 19 / 24.5 피해이며 총 60 피해·60 정기입니다. 기존 첫 스킬의 60 정기 단발 비용을 세 타로 나눠 초반에도 짧게 사용할 수 있게 한 가안입니다. 돌진과 연계의 조작성, 적 체력 대비 처치 시간은 플레이 후 재조정합니다.

돌진은 NavMeshAgent가 이동을 담당하며 NavMesh 경계와 월드 장애물에서 멈춥니다. 지정 거리까지 벽을 통과하는 순간이동은 금지합니다. 벽 때문에 줄어든 거리를 이후 프레임에 몰아서 보상하지 않습니다. 피해 시점에 전방 중심의 구형 범위와 반각으로 대상을 판정하며, 같은 적의 여러 콜라이더에는 한 번만 피해를 줍니다. 스킬마다 모든 적을 동일하게 밀지 않고 기존 적·보스의 피격 저항과 스킬 슈퍼아머 정책을 적용합니다.

### 수치 강화

| 강화 | 재료 | 1레벨 효과 | 상한 가안 |
| --- | --- | --- | --- |
| 피해 | 빗자루 재료 1개 | 피해 배율 +8%p | 5레벨, +40% |
| 쿨타임 | 빗자루 재료 1개 | 쿨타임 -4%p | 5레벨, -20% |
| 효율 | 빗자루 재료 1개 | 소모 자원 -4%p | 5레벨, -20% |

강화는 3단계 조합 완료 후 열립니다. 복리 대신 레벨당 가산을 사용합니다. 진행 중 쿨타임을 소급해 줄이거나 파츠를 회복하지 않습니다. 감소 총합이 80% 이상인 엑셀은 변환 단계에서 거부합니다. 모션 속도·돌진 거리는 이번 강화 축에 포함하지 않습니다.

### 유대와 분기

실제로 적을 명중한 스킬 한 타마다 유대 1점 가안을 부여합니다. 광역 공격으로 여러 적이나 콜라이더를 맞혀도 해당 타의 유대는 한 번만 증가합니다. 재료 조합만으로 유대를 올리지 않으며 수치 강화와 유대는 별도 성장 축입니다.

유대가 있거나 조합으로 성장한 개체는 기존 직접 소비 API로 제거할 수 없습니다. 정식 분해 UI에서는 개체명·유대·성장 단계·사라지는 기록을 보여주는 경고와 재확인이 필요합니다. 현재는 **소비 자체를 거부**하며 정식 분해 확인창은 후속 구현입니다. 유대 보상, 장정형의 능력 변화와 별명·관계 이벤트도 후속 범위입니다.

월도 조각 분기는 같은 개체의 `branchId`만 바꾸고 고유 ID·유대·이름·조합 단계·강화 이력을 보존하는 구조로 확장합니다. 장정형 역시 기존 도깨비를 계승합니다. 현재 `WOLDO_BROOM` 행은 후보이며 `enabled=FALSE`입니다. 피해 ×1.2, 비용 ×1.1은 검토 가안이지 플레이에 적용된 효과가 아닙니다. 기존 월도 보상을 재료로 소모하지 않고, 후속 드롭 테이블에 월도 조각을 따로 연결해야 합니다.

## 상태와 데이터 소유자

| 상태 | 소유자 | 보존 범위 |
| --- | --- | --- |
| 고유 ID·추첨 능력치·내구도 | `PartInstanceData` | 기존 객체 및 씬 인계 |
| 조합 수·유대·세 강화 레벨·분기 ID | `DokkaebiGrowthState` | 같은 파츠 객체에 부착 |
| 빗자루 재료 수량 | `PrototypePartInventory` | `TutorialSessionTransfer`에 함께 인계 |
| 배치와 키 할당 | `PrototypeBlueprintLoadout` | 같은 객체 참조 유지 |
| 현재 순서·입력 예약·유예·쿨타임 | `PrototypeSkillUseController` | 현재 컨트롤러 수명. 연계는 씬 전환에 인계하지 않음 |
| 수치 원본 | 엑셀 | 기획자가 수정 |
| 런타임 읽기용 수치 | JSON, `DokkaebiGrowthDatabase` | Play 시작 시 캐시. 변환 후 Play 재시작 필요 |

상태 전이는 대기 → 첫 타 승인 → 돌진·준비 → 접촉 → 회복 → 다음 타 대기 또는 종료입니다. 중간 타 입력 실패는 그 타를 건너뛰지 않습니다. 다음 타 대기 중 다른 스킬을 쓰더라도 빗자루의 개체 쿨타임은 초기화되지 않습니다.

현재 인계는 메모리 전용입니다. 앱 종료 후 유지되는 세이브는 구현하지 않았습니다. 정식 세이브에는 원본 ID와 고유 개체 ID, 추첨 값, 현재 내구도, 성장 필드, 재료 수량, 배치 좌표와 키 소유 ID가 필요합니다. 기존 세이브에 성장 필드가 없다면 빗자루를 1단계·유대 0·강화 0·BASE로 이전하며 이미 저장된 능력치와 내구도를 유지해야 합니다. 정식 씬 전환 쿨타임 인계와 분기 이전 정책은 추가 구현 대상입니다.

## 엑셀과 JSON 계약

엑셀의 1행은 코드 필드명, 2행은 한국어 설명, 3행은 단위, 4행 이후는 값입니다. 노란 배경의 숫자가 주요 편집 항목입니다. 수식 캐시·숫자 문자열·빈 필수 셀은 허용하지 않습니다. ID와 영문 열 이름을 변경할 때는 코드 스키마를 함께 수정합니다.

| 시트 | 행의 의미 | JSON 배열 |
| --- | --- | --- |
| Stages | 조합 단계별 연계·쿨타임 정책 | stages |
| Actions | 연계 한 타의 판정·모션·이동·비용 | actions |
| Recipes | 한 단계 상승 레시피 | recipes |
| Enhancements | 강화 축·재료·상한·효과 | enhancements |
| Branches | 이종 조합 분기 후보 | branches |

### 전투 필드

| 필드 | 단위와 의미 |
| --- | --- |
| id, label | 고정 식별자, 표시명 |
| step | 1~3타. 중복·누락 불가 |
| visualId | 기존 빗자루 SWEEP / THRUST 표현 연결 ID |
| motion | SweepLeft / SweepRight / Thrust. 순서 고정 |
| damageFlat, damageScale | 고정 피해, 파츠 공격력 배율 |
| resourceCost | 각 타의 정기 비용 |
| duration, impactRatio | 모션 초, 접촉 비율 0 초과 1 미만 |
| dashDistance, dashDuration | 돌진 m, 초. 돌진이 접촉 이후까지 지속되지 않도록 검사 |
| hitRadius, forwardOffset | 피해 구 반경 m, 캐릭터 기준 전방 중심 거리 m |
| halfAngle | 전방 반각. 총 부채꼴 각도는 두 배 |
| stagger, knockback, knockdown | 경직 초, 밀림 m, 넘어짐 초. 0은 없음 |
| comboCount | 해당 조합 단계의 최대 공격 횟수 |
| cooldown, comboWindow, inputBuffer | 공유 쿨타임 초, 타 종료 후 연계 유예 초, 모션 종료 전 입력 예약 초 |
| bondPerHit | 유효 명중 타당 유대 증가량 |

### 제작 필드

레시피의 `fromStage`와 `toStage`는 Stages ID이며 한 단계만 전진합니다. `materialId`와 `quantity`는 재료 종류와 요구 수량입니다. 강화의 `requiredStage`, `maxLevel`은 해금 조건과 레벨 상한이고, 세 `PerLevel` 필드는 피해 증가와 쿨타임·비용 감소 비율입니다. 분기의 `enabled`는 현재 FALSE만 허용합니다. 분기 동작을 구현하지 않은 채 TRUE로 바꾸는 것은 오류로 처리합니다.

강화 행은 POWER의 `damagePerLevel`, HASTE의 `cooldownReductionPerLevel`, EFFICIENCY의 `costReductionPerLevel`만 사용합니다. 각 행의 나머지 효과 열은 0이어야 합니다. 복합 효과 강화는 별도 스키마 확장 대상입니다.

JSON은 `schemaVersion=1`, `balanceVersion`, 원본 파일의 `sourceSha256`과 다섯 배열을 가집니다. 재생성 전후 원본 해시와 검증 결과를 비교할 수 있습니다. 플레이어 성장 상태를 밸런스 JSON 안에 저장하지 않습니다.

## 예외 처리와 검증

- 중복 ID, 알 수 없는 단계 참조, 누락된 열·시트, 음수·NaN·무한대, 잘못된 타입은 변환 실패입니다.
- 조합 순서를 건너뛰거나 공격 방향 순서를 바꾸는 표는 거부합니다. 새 규칙은 스키마·코드·명세와 함께 변경합니다.
- 엑셀 수식은 결과 캐시가 오래되었을 수 있으므로 허용하지 않습니다. 이번 표에는 직접 입력한 수치만 사용합니다.
- 검증 완료 전에는 출력 JSON을 건드리지 않고, 완료 후 임시 파일에서 원자적으로 교체합니다.
- Unity에서도 최소 스키마와 안전 범위를 검증합니다. 데이터가 없거나 잘못되면 새 성장 기능을 활성화하지 않고 오류를 알립니다.
- 상한·재료 부족·파손 상태에서 조합·강화를 누르면 이유를 표시하고 재료를 유지합니다.

## UI와 연출

Tab → 청사진 편집 → 빗자루 선택 순서를 유지합니다. 파츠 상세에 실제 예상 피해·각 타 비용·돌진 거리·공유 쿨타임을 보여주고, 아래에 유대·조합 수·재료·세 강화 레벨과 제작 버튼을 둡니다. 조합 버튼은 두 번째 입력에서 확정합니다. 정식 제작 시설과 비용 미리보기 팝업은 후속 UX입니다.

![빗자루 3단계 조합과 수치 강화 UI](../../../07_에셋/이미지/개발_기록/2026-10-08/청사진_빗자루_성장_UI.png)

별도 Unity 검증 씬의 실제 화면입니다. 표시 피해는 개체의 추첨 공격력과 강화 레벨에 따라 달라집니다.

Unity Editor와 Development Build에는 **플레이테스트: 빗자루 재료 +1** 버튼을 둡니다. 이는 조합·강화를 바로 시험하기 위한 지급 기능이며 정식 배포 빌드에는 나타나지 않습니다. 현재 튜토리얼의 첫 빗자루 보상은 한 개이므로 2·3단계 시험에는 이 버튼 또는 추가 월드 Pickup이 필요합니다. 일반 몹 반복 파밍과 정식 드롭 확률은 아직 연결하지 않았습니다.

기존 플레이어 8방향 이미지와 독립 빗자루 프리팹, 별도 궤적을 재사용합니다. 왼쪽·오른쪽 쓸기는 빗자루 경로와 궤적을 반대로 하고, 찌르기는 자루 끝을 접촉점으로 사용합니다. 돌진 중 빗자루 현현 위치는 캐릭터의 이동을 따라가되 손에 붙이지 않습니다. 새 좌우 전용 플레이어 원화와 월도 결합 원화는 별도 제작 범위입니다.

## 적용 방법

게임 저장소 `Tools/Data/README.md`를 기준으로 실행합니다.

```powershell
# C:\GitHubProjects\ERGOSQUARE-ARCHITECT에서 실행
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/Data/Export-Growth.ps1

# JSON이 현재 엑셀과 일치하는지 검사
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/Data/Export-Growth.ps1 -Check
```

Unity 메뉴 `ERGOSQUARE → Data → 도깨비 Excel → JSON 재생성`에서도 변환합니다. 엑셀 저장 → Play 종료 → 변환 → Unity import → Play 순서입니다. JSON을 수동으로 수정하면 다음 변환에서 사라집니다. 엑셀 파일을 다른 경로로 옮기면 `-Workbook` 옵션을 사용합니다.

2026-10-08 자동 검증: 엑셀 변환·실패 시 JSON 보존 시험 13개, 별도 Unity 플레이 모드 성장 시험 57개 항목 통과. 좌우·찌르기 연계, 수치 적용, 개체·유대·내구도 유지, 씬 인계, 연계 만료, 벽·NavMesh 경계 돌진을 확인했습니다. 기존 독립 빗자루 모션과 월도 보상·전투 회귀 검증도 통과했습니다. 원본 튜토리얼 씬 파일은 변경하지 않았습니다.
