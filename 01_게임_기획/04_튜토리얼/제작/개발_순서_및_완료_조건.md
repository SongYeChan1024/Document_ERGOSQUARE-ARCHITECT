> [!IMPORTANT]
> 문서 상태: 초안. 일정은 아니며 의존성을 기준으로 한 제작 순서입니다.

## 개발 순서

| 단계 | 결과물 | 다음 단계 조건 |
| --- | --- | --- |
| 1. 조작 샌드박스 | 쿼터뷰 카메라, 우클릭 이동, 좌클릭 공격, Space 정신 집중 | 이동·조준·집중 상태가 충돌 없이 동작 |
| 2. 전투 샌드박스 | 소형 도깨비 공용 리그, 피해, 스킬 2~3개, 사망·월드 게임오버, 개발용 재현 | 짧은 교전을 반복 검증 가능 |
| 3. 청사진 편성 | 격자에 코어·수납·방벽 배치·저장 | 유효성 검사가 동작 |
| 4. 에르고스퀘어 전개 | 편성 데이터의 월드 오브젝트 변환 | 배치, 충돌, 취소가 동작 |
| 5. 파츠 피해 | 적의 파츠 공격, 엄폐, 내구도와 파괴 | 코어 활성 능력 중단과 수납 기능 차단 검증 |
| 6. 아이템 루프 | 자동 획득, `B` 가방, 회복제·코어 활성제 | 획득·사용·파밍 차단이 연결 |
| 7. 플롯 프레임워크 | 트리거, 목표, 개발용 상태 스냅샷, 회상·시스템 창 | TUT-00~08을 임시 자산으로 완주 |
| 8. 레벨 통합 | A~G 구역, 토벌팀 기록, 영혼 구조, 월도 보스, 폐쇄·복귀 | 처음부터 끝까지 중단 없이 플레이 |
| 9. 가독성·연출 | VFX, UI, 사운드, 회상, 복귀 장면 | 외부 테스터가 목표·위험을 이해 |
| 10. 플레이테스트 | 기록, 문제 분류, 다음 버전 결정 | 중단·유지·확장 결정 |

## 전체 완료 조건

- [ ] 처음 시작한 플레이어가 개발자 조작 없이 TUT-00~08을 완주할 수 있다.
- [ ] 모든 필수 조작이 플레이 상황 속에서 한 번 이상 사용된다.
- [ ] 코어·소형 주머니·방어 플레이트의 배치가 전투와 반출 결과에 영향을 준다.
- [ ] 코어가 엄폐물이면서 공격 대상이고, 파괴 시 자원·스킬·활성 능력이 중단됨을 이해한다.
- [ ] 주머니가 파괴되면 내용물 반출과 해당 주머니 수납이 차단되며 직접 수납은 빈 칸만큼 유지된다.
- [ ] 플레이어가 잠복 게이트에 흡인되어 에르고스퀘어가 발현했고 설계자 코드네임을 받았음을 이해한다.
- [ ] 정상 기억 투영형 도깨비와 폭주한 영혼 주입형 도깨비의 차이를 이해한다.
- [ ] 게이트 폐쇄와 민간인 구조가 마지막 목표로 명확히 인식된다.
- [ ] 정식 사망은 월드 게임오버로 이어지고 개발 빌드에서만 원하는 플롯을 빠르게 재현할 수 있다.
- [ ] 튜토리얼 전용 코드에 과도하게 결합되지 않은 재사용 가능한 시스템으로 구성된다.
- [ ] 치명적인 진행 불가, 저장 손상과 데이터 소실이 없다.

## 단계별 게이트

각 단계는 다음 질문에 `예`라고 답할 수 있을 때만 넘어간다.

1. 예상한 입력과 결과를 반복 재현할 수 있는가?
2. 실패했을 때 원인을 확인할 수 있는가?
3. 이 기능을 튜토리얼 밖의 다른 레벨에서도 호출할 수 있는가?
4. 새로운 기능이 이전 단계의 조작과 규칙을 깨뜨리지 않는가?

## 종료 판정

튜토리얼을 완성했다는 이유로 자산과 콘텐츠를 계속 늘리지 않는다. 완료 조건을 통과하면 결과를 기록하고 다음을 결정한다.

- 핵심 가설이 통하면: 일반 게이트·허브·협동으로 확장
- 조작은 통하지만 전개가 약하면: 청사진·파츠 위험 재설계
- 서사는 이해되지만 흐름이 끊기면: 회상·시스템 안내 축소
- 운영 불가능한 수준이면: 핵심 시스템 샌드박스로 되돌아감
