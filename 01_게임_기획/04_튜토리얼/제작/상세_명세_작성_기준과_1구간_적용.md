# 상세 명세 작성 기준과 튜토리얼 1구간 적용

작성자: 송예찬 · 작성일: 2026-09-14 · 상태: 검토 초안

[종합 기획서](../../../00_프로젝트_개요/에르고스퀘어_종합_기획서_초안.md) · [튜토리얼](../README.md) · [테스트 체크리스트](테스트_체크리스트.md)

## 적용 목적

[위키독스의 게임 상세 기획서 기본 템플릿](https://wikidocs.net/371390#1)을 참고해 구현에 필요한 조건과 검증 근거를 보강합니다. 예시 게임의 조작·상점·보상 규칙을 에르고스퀘어의 확정 사양으로 가져오지 않습니다. 아래 항목과 사례는 프로젝트의 기존 문서 및 현재 코드를 바탕으로 작성했습니다.

종합 기획서가 게임 규칙과 서사의 기준을 소유하고, 이 부록은 코드 동작과 수용 시험의 근거를 기록합니다. 데이터 수치의 원본 위치와 변경 이력을 함께 기록해 같은 값을 여러 곳에서 따로 수정하지 않게 합니다.

## 기능 문서에 추가할 기록

| 기록 항목 | 에르고스퀘어에서 작성할 내용 |
| --- | --- |
| 식별·범위 | 기능 ID, 해당 튜토리얼 구간, 선행 기능, 이번 구현 범위 |
| 의도·실행 조건 | 플레이어가 배우는 판단, 입력, 허용 상태와 차단 사유 |
| 상태 변화 | 실행 전 상태, 성공 결과, 취소 또는 실패 후 남는 상태 |
| 데이터·소유자 | 실제 필드명·타입·단위·초기값과 원본 에셋 또는 코드 |
| 화면·연출 | 안내 문구, 표시·종료 시점, 게임플레이 상태와 연결 방식 |
| 예외·복구 | 중복 이벤트, 참조 누락, 사망과 완료 경합, 재진입 처리 |
| 완료 판정 | 시작 조건·행동·관찰 결과로 작성한 시험과 실제 확인 날짜 |
| 변경 추적 | 변경 이유, 관련 문서·코드·데이터, 후속 검증 |

기획 상태는 `합의 / 가안 / TBD`, 구현 상태는 `미구현 / 부분 구현 / 구현`, 검증 상태는 `미검증 / 부분 확인 / 통과`로 따로 기록합니다. 컴파일 통과는 플레이 완료를 의미하지 않습니다.

## 기존 문서의 역할

- 개요·세계관·시나리오: [종합 기획서](../../../00_프로젝트_개요/에르고스퀘어_종합_기획서_초안.md)에서 읽고 각 세부 문서로 이동합니다.
- 조작·전투·아이템: [핵심 플레이](../../01_핵심_플레이/README.md)와 시스템 상세 부록에서 구현 근거를 확인합니다. 규칙은 종합 기획서를 우선합니다.
- 장비·코어·스킬 및 문화권별 차이: [통합 문서](../../01_핵심_플레이/장비_코어_스킬/README.md)를 유지합니다.
- 장면 진행: [플롯별 상세 명세](../시나리오/플롯별_상세_연출_및_구현_명세.md)에 성공·실패 조건을 연결합니다.
- 테스트: [체크리스트](테스트_체크리스트.md)에 재현 절차와 결과를 남깁니다.

## 적용 사례: 튜토리얼 첫 전투 구간

문서 식별자 `TUT-SLICE-01`은 이번 기록용 ID이며 런타임 데이터 ID가 아닙니다. 대상 씬은 `Tutorial_Stage01_Awakening`입니다. 이 씬의 네 단계는 정식 시나리오 TUT-00~08 전체를 구현한 것으로 간주하지 않습니다.

현재 코드 확인 대상은 Unity 저장소의 `Assets/_ERGOSQUARE/02.Scripts/Content/Tutorial_Dokkaebi/Runtime/TutorialStageOneController.cs`입니다. 물리적 코어 전개·월도 보스·허브 인계는 이 제어기의 범위 밖입니다.

### 정상 진행과 현재 데이터

| 현재 상태 | 판정 입력 | 결과 |
| --- | --- | --- |
| FindBroom | inventory.HasBroom이 false | 획득 목표, 차단막 켜기, 적·완료 표식 끄기 |
| ConfigureBlueprint | 빗자루 보유, 배치 또는 할당 불충족 | 청사진 설정 목표, 차단막 유지 |
| DefeatDokkaebi | 배치된 빗자루와 8개 슬롯 중 하나의 소유 파츠 참조 일치 | 전투 목표, 차단막 끄기, 적 켜기 |
| Completed | 연결된 적의 Defeated 이벤트 | 완료 목표, 적 끄기, 완료 표식 켜기 |

| 필드·속성 | 타입 | 현재 역할 |
| --- | --- | --- |
| currentPhase | Phase enum | 씬에 직렬화된 진행 단계 |
| inventory | PrototypePartInventory 참조 | 빗자루 보유 상태 원천 |
| loadout | PrototypeBlueprintLoadout 참조 | 파츠 배치·슬롯 할당 원천 |
| combatEnemyHealth | PrototypeDamageReceiver 참조 | 처치 이벤트 원천 |
| configurationBarrier / combatEnemy / completionBeacon | GameObject 참조 | 진행에 따른 월드 활성 상태 |
| CurrentObjective | string | 현재 목표 문구, 현재는 코드에 직접 정의 |

입력 흐름은 우클릭 이동, G 획득, Tab 전개 HUD의 편집 버튼, 배치·QWERASDF 할당, Space 정신 집중, 할당한 스킬 사용입니다. 정신 집중은 코어 에너지 풀을 회복하며 별도 자원 게이지를 만들지 않습니다. 각 입력의 세부 차단 조건은 소관 조작·편집 명세를 따릅니다.

완료 표식 활성화는 현재 연출 결과입니다. 표식 도달에 따른 다음 씬 이동, 보상 지급 또는 저장 완료를 구현했다고 판정하지 않습니다.

### 예외와 결정이 필요한 사항

| 상황 | 현재 코드 또는 확인 근거 | 필요한 판단·검증 |
| --- | --- | --- |
| 적 처치 중 비활성화 | 테스트 적이 활성 여부를 검사하도록 9월 7일 수정 | 이벤트 구독 순서를 바꿔도 코루틴 오류가 없는지 재현 시험 |
| 전투 진입 후 스킬 할당 해제 | 변경 이벤트로 ConfigureBlueprint로 돌아가 적을 끌 수 있음 | 전투 중 편집 제한 여부, 적 체력·콜라이더·연출 재활성화 정책 TBD |
| inventory 참조 누락 | 미보유와 같은 분기로 들어감 | 구성 오류 안내와 진행 중단 방식을 정해야 함 |
| 전투 단계 밖 처치 이벤트 | HandleEnemyDefeated에 현재 단계 검사가 없음 | 잘못된 완료 방지 조건 검토 |
| 완료 후 이벤트 반복 | PhaseChanged는 같은 단계에서 재발행하지 않음 | 향후 보상·저장 추가 시 별도 중복 방지 필요 |
| 플레이어 사망과 적 처치 동시 발생 | 이 제어기에는 사망 경합 처리가 없음 | 최종 실패 규칙에 맞는 우선순위 TBD |
| 씬 재진입·저장 복원 | 저장 서비스 연동이 이 제어기에 없음 | 진행·소지품·처치 상태의 복원 단위 TBD |

위 표는 발견 사항과 후속 기획 과제이며 이번 문서 작업에서 게임 코드를 수정하지 않았습니다.

### 수용 시험

- [ ] 초기 상태에서 접근 후 G로 획득하면 목표가 청사진 설정으로 바뀐다.
- [ ] 배치만 하고 스킬을 할당하지 않으면 차단막과 적 상태가 유지된다.
- [ ] 배치된 빗자루에 슬롯을 할당하면 차단막이 사라지고 적이 활성화된다.
- [ ] 자원을 모아 적을 처치하면 완료 목표와 표식이 표시된다.
- [ ] 처치 시 비활성 코루틴 오류가 없고 튜토리얼 적이 자동 부활하지 않는다.
- [ ] 전투 중 편집·재진입의 정책 확정 후 해당 경계 조건을 시험한다.

9월 7일 기록에서 확인된 범위는 컴파일, 씬 반복 생성, 이동과 G 안내 표시입니다. 전체 흐름과 오류 수정 후 처치 재현은 통과로 표시하지 않습니다. 근거: [개발일지](../../../04_프로젝트_관리/개발_일지/2026-09-07_튜토리얼_1구간_맵과_진행_흐름_구축.md).

## 구현 요청에 넘길 정보

작업을 시작할 때 기능 ID와 기준 문서, 현재 코드 경로, 이번에 바꿀 행동, 유지할 인터페이스, 결정된 예외 정책, 통과해야 할 수용 시험을 묶어 전달합니다. 미결정 항목을 구현자가 임의의 게임 규칙으로 확정하지 않도록 TBD 목록도 함께 전달합니다.

예를 들어 다음 요청은 `TUT-SLICE-01의 처치 처리 검증`으로 한정하고, 활성 상태에서 처치하는 경우와 다른 구독자가 먼저 비활성화하는 경우를 함께 확인하도록 작성할 수 있습니다. 보상 지급·월드 종료 정책은 별도 합의 후 추가합니다.
