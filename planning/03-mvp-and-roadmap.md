# MVP와 로드맵

## MVP 검증 질문

> 플레이어가 전투력을 얻기 위해 파괴 가능한 청사진을 전장에 노출하고, 팀과 함께 그 약점을 보호하는 구조가 실제로 재미있는가?

## 필수 구현 범위

- Photon PUN2 접속, 룸 생성·입장
- 3~4인 플레이어 이동 및 상태 동기화
- 전술 프레임 선택
- 격자 기반 모듈 배치
- 에르고스퀘어 전개·회수
- 모듈 설치 시간과 파괴 상태
- 자원 코어와 전술 자원 생성
- 직접 공격 1종 이상
- 일반 침식체와 코어 우선 공격 AI
- 전투 시작·종료와 결과 UI
- AI 교관의 기본 안내와 결과 피드백

## 우선순위

| 우선순위 | 프레임 | 이유 |
| --- | --- | --- |
| 1 | 거너 | 조준과 사격이 직관적이며 핵심 루프 시연에 적합 |
| 2 | 뱅가드 | 전방 전개와 코어 보호 역할이 명확 |
| 3 | 리액터 | 원격 전개라는 공간 조작 차별점을 전달 |
| 확장 | 링커 | 분할 노드와 네트워크 의존 관계로 구현량이 큼 |

## 7주 기준 로드맵

1. 기획 확정 및 Unity·Photon 프로젝트 세팅
2. 룸과 플레이어 동기화
3. 격자 편성과 모듈 데이터 구조
4. 에르고스퀘어 전개와 자원 시스템
5. 직접 전투, 침식체 AI, 웨이브
6. 결과 분석과 AI 교관
7. 네트워크 점검, 버그 수정, 시연 준비

## 기술 검토

| 분야 | 후보 기술 |
| --- | --- |
| 게임 엔진 | Unity / URP |
| 멀티플레이어 | Photon PUN2 |
| UI | Unity UI, TextMeshPro |
| 데이터 | ScriptableObject, JSON |
| AI 교관 | 생성 AI API |
| 최적화 | Object Pooling, LOD, Occlusion Culling |

## 주요 리스크

- 청사진·직접 전투·네트워크를 동시에 구현할 때 범위가 급격히 커질 수 있다.
- 모듈 단위의 지속 동기화는 네트워크 부하를 만든다.
- 링커의 분할 노드는 의존 관계와 상태 동기화가 복잡하다.
- 생성 AI를 핵심 진행 조건으로 사용하면 응답 실패가 플레이를 막을 수 있다.

## 대응 원칙

- MVP 프레임과 모듈 종류를 제한한다.
- 배치 정보는 전개 시점에 묶어서 전송하고 상태 변화만 이벤트로 동기화한다.
- 몬스터 AI는 Master Client 중심으로 처리한다.
- AI 교관은 규칙 기반 기본 응답을 제공하고 생성 AI는 보조 피드백으로 사용한다.
- 기획 수치와 실제 프로토타입 수치를 분리해 기록한다.
