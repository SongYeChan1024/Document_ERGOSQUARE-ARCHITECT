# 3인칭 비교 씬 조작과 검수 명세

문서 상태: 초안 · 비교용 프로토타입 / 작성자: 송예찬 / 기준일: 2026-10-21

20일 세션 마감 기준 일반공격은 VARCO 원본 ‘검 2단 베기’ 2타이며 마지막 찌르기는 제거했다. 두 타격 모두 공격 중 마우스 수평 에임을 따른다. 아래 초기 3타·파생 모션 검수는 비교 이력이며 현재 적용은 ‘원본 2타와 에임 추적’ 항목을 따른다. [마감 개발 일지](../../04_프로젝트_관리/개발_일지/2026-10-20_검_2단_베기와_공격_중_마우스_에임_추적.md)

21일 후속 조정은 원본 모션 곡선을 유지한 1.7배 재생, 단타 종료 후 0.28초 자세 복귀, 파츠별 스킬 쿨타임, B 편집 / Tab 필드 배치 분리다. 상세 내용과 검증 범위는 아래 ‘단타 복귀·쿨타임·필드 배치’ 항목을 따른다.

Space는 이후 사용자 요청에 따라 점프로 변경했다. 정신 집중은 왼쪽 Ctrl로 옮기고, VARCO 점프 모션과 실제 수직 이동·착지를 연결했다. 상세 내용은 ‘Space 점프’ 항목을 따른다.

## 목적

기존 쿼터뷰 데모의 씬·플레이어·입력 자산을 보존하면서 3인칭 카메라와 직접 이동의 조작감을 비교한다. 이 실험은 본편 조작 방식의 최종 변경이 아니다.

## 사용자 흐름

Unity 메뉴 `Tools → ERGOSQUARE → Comparison → Open Third Person Comparison`에서 씬을 열고 Play한다. 마우스로 시점을 바꾸며 WASD로 이동하고, 표적에 접근해 좌클릭 2타 공격과 Q/E 스킬을 시험한다. B로 새 인벤토리를 열어 장착·해제와 스킬 배정을 바꾼다. Tab으로 필드 배치 미리보기를 연 뒤에도 이동과 마우스 시점 조작을 유지한다. 중앙 조준점으로 바닥을 골라 좌클릭으로 설치하며 Tab/Esc로 취소한다. 이미 전개했다면 Tab → 좌클릭으로 회수한 후 다시 조준하여 설치한다. 시작점 옆 보급대에서 F로 체력·정기·약품·표적 체력을 회복한다.

## 동작 규칙

- 카메라 기준 WASD 이동이며 대각선 속도를 정규화한다. Shift는 비교용 달리기다. 기본 이동 속도 2.2, 달리기 4, 회전 속도 초당 720도는 가안이다.
- 이동 중 캐릭터는 카메라 기준 이동 방향을 향한다. 기본 공격과 스킬 시작은 화면 중앙 광선이 가리키는 점을 플레이어 위치에서 향하는 수평 방향으로 실행한다. 숄더뷰의 옆 이동으로 생기는 시차를 보정한다. 단, 플레이어 전방 깊이 1.25m보다 가까운 표면은 같은 광선을 해당 깊이 평면까지 연장하여 수평 방향을 계산한다. 가까운 바닥·가림 물체 때문에 거의 옆을 향하는 증폭을 막으며 실제 조준 충돌점은 유지한다. 기본 공격 클릭은 해당 프레임 마우스 시점 갱신 후 소비한다. 기본 공격 중에는 현재·예약된 타격 방향을 마우스 에임과 함께 갱신하고, 기존 공격·스킬의 이동 잠금과 타격 계약은 유지한다.
- 기존 `PlayerNavMotor`의 명시적 선택 기능으로 직접 이동을 사용한다. 기존 데모는 기본 클릭 이동 경로를 유지한다. 벽·표적의 이동 제약은 NavMesh와 표적 장애물로 처리한다.
- 카메라는 오른쪽 어깨 너머에서 캐릭터를 화면 왼쪽에 크게 둔다. 뒤 거리 2.6m, 오른쪽 오프셋 0.85m, 루트 기준 피벗 높이 0.55m, 초기 수직 각도 8도, 수직 회전 -30~65도, 감도 0.13은 가안이다. 플레이어 루트의 기존 Agent 높이 오프셋을 고려한다. 피벗부터 옆·뒤 이동 전체를 구체 캐스트로 검사해 벽·바닥·천장 앞에서 카메라 거리를 줄인다.
- 검 끝의 잔상은 실제 무기 메시를 따라가며, 스킬 방향 가이드는 실제 실행 상태를 따른다. 시각 효과는 피해를 발생시키지 않는다.
- 시점 조작과 필드 배치 중 화면 정중앙에 십자선 없는 작은 흰색 점을 표시하고, 기본 공격 재생 중에는 호박색으로 바꾼다. 어두운 테두리는 밝은 배경에서도 보이도록 유지한다. 장비/스퀘어 편집·커서 해제·사망 상태에서는 숨긴다. 조준점은 UI 클릭을 가로채지 않는다. 현재 근접 공격은 조준 위치를 향하는 수평 방향만 사용하므로 수직 명중점이나 타격 성공 표시는 아니다.
- Tab 전개 중 WASD·달리기·마우스 회전을 유지하며, 좌클릭은 설치/회수 요청으로만 처리한다. 중앙 광선의 첫 충돌이 완만한 Ground 표면이어야 한다. 선택 스퀘어 중심을 조준점 근처 월드 격자에 맞추고 다른 스퀘어의 상대 오프셋을 유지한다. 전개 중심까지 수평 거리 10m는 가안이다. 설치물은 선택한 월드 위치에 남으며 회수 기준도 그 위치를 사용한다.
- 비교용 필드 격자는 1칸 1m다. 첫 3×3은 3×3m, 6×6으로 확장하면 6×6m이며 가방·청사진의 논리 칸 수와 파츠 점유 칸은 바꾸지 않는다. 다른 스퀘어의 파츠 점유 영역도 표시하며, 장애물이나 지면 조건을 실패한 파츠는 빨간색과 구체적인 사유로 구분한다. 기존 쿼터뷰의 2m 격자는 유지한다.
- 인벤토리에서는 커서를 해제하고 이동·공격·스킬·소모품 입력을 차단한다. 메뉴 밖 Esc는 커서만 해제하며 다시 좌클릭하면 조작을 재개한다.

## 입력과 출력

| 입력 | 비교 씬 기능 |
| --- | --- |
| WASD | 카메라 기준 이동 |
| 마우스 이동 | 카메라 회전 |
| 좌클릭 | 일반 조작: 원본 검 2단 베기 / Tab 전개: 조준한 곳에 설치 / 이미 전개한 상태의 Tab 화면: 회수 |
| Q E R T Z X C V | 스킬 슬롯 0~7 |
| F | 기존 상호작용 컨트롤러를 통한 보급대 사용 |
| 1 2 3 4 | 소모품 슬롯 0~3 |
| Shift | 달리기 |
| Space | 지상에서 점프; 공중 재점프 없음 |
| 왼쪽 Ctrl | 기존 정신 집중·정기 회복 |
| B | 새 장비·스퀘어 UI |
| Tab | 필드 배치 미리보기 열기·닫기; 편집창에서는 닫기 |
| Esc | 편집창 닫기, 필드 배치 취소 또는 일반 조작 중 커서 해제 |

별도 Input Actions 자산에서 슬롯의 물리 키만 바꾼다. 슬롯 액션의 기존 이름은 내부 인덱스 계약으로 유지한다. 새 UI의 버튼·아이템 배지·키 배정 입력은 비교 씬의 QERTZXCV를 표시하고 사용한다.

## 상태

기존 FSM의 Idle·Moving·BasicAttack·Skill·Focus·Menu·Dead와 실제 Animator를 재사용하고 Jumping·Falling·Landing을 기존 enum 값 뒤에 추가한다. 새 이동기는 스킬·집중·메뉴·사망과 공격의 이동 억제를 지킨다. FSM·Animator는 씬의 플레이어 루트 `Demo Player Rig`에서 재생 전에도 확인한다.

## 데이터

- 비교 씬: `Assets/_ERGOSQUARE/01.Scenes/Comparison/ThirdPerson_Comparison.unity`
- 입력·재질·베이크된 내비게이션: `Assets/_ERGOSQUARE/08.Data/ThirdPersonComparison/`

- 시험용 지급과 약품 상태는 이 씬의 메모리에서만 관리하며 기존 튜토리얼 세션 인계·영구 저장에 기록하지 않는다.

## 예외 처리

보급은 스킬의 기억된 냉각을 초기화하지 않는다. 빈 슬롯·자원 부족·냉각 중 사용·이미 가득 찬 소모품 사용은 HUD에서 상태를 확인한다. 커서를 해제한 메뉴 밖 상태에서는 게임플레이 입력을 비활성화한다. 초깃값과 표적은 비교용이며 기존 진행·보상을 건너뛰는 기능을 본편에 추가하지 않는다.

## UI와 피드백

상단에는 조작 안내와 체력·정기·FSM 상태, 하단에는 8개 스킬과 4개 소모품 슬롯을 표시한다. 표적 위에는 실제 체력을 표시한다. 장비·에르고 스퀘어는 기존 새 3열 UI를 사용하며, 키 표시 재정의는 비교 씬 인스턴스에만 적용한다. 정지 표적과 바닥 거리선·벽·카메라 장애물이 있는 별도 연습장을 사용한다.

## 완료 조건

재생 전 실제 FSM/Animator 연결, 물리 입력을 통한 8개 스킬 슬롯과 F 상호작용, 카메라 기준 이동·정지·속도 제한, 원본 2타의 정확히 2회 타격과 공격 중 에임 전환, 실제 스킬 피해·자원·냉각, 소모품 사용과 입력 차단, 카메라 장애물 대응을 별도 Unity에서 확인한다. 기존 자산의 해시와 클릭 이동·Animator 회귀를 확인한다. 초기 검수 근거는 `Tools/ArtReview/ThirdPerson_Comparison_20261019`, 현재 일반공격 검수는 `Tools/ArtReview/Varco_DoubleSlash_LiveAim_20261021`에 보관한다.

### 초기 3타 비교판 검수 결과

Unity 6000.3.7f1에서 편집 모드 연결·바인딩 11개와 비교 씬 실제 플레이 검사 45개를 통과했다. Input System 키보드·마우스 이벤트로 이동·공격·8개 슬롯·F·소모품을 실행했다. 3단 공격에서 타격 3회와 총 피해 45, 빗자루의 실제 피해, 월도 실행, 벽 앞 이동과 카메라 거리 축소를 확인했다. 원래 데모의 클릭 이동·Animator·전투 회귀 210개도 통과했다. 반복 프레임 검사를 포함한다.

기존 씬·조립 프리팹·테스트/데모 플레이어·모션/Animator·원래 입력·빌드 씬 목록 등 85개 기존 자산의 해시가 동일하다. 비교 씬은 기존 빌드 씬 목록에 추가하거나 기존 시작 씬을 대체하지 않는다. 공통 코드의 직접 이동과 UI 키 재정의는 비교 씬에서 명시적으로 사용하는 선택 기능이다.

이 결과는 별도 에디터에서 수행한 자동 기능 검사이며, 사용자의 메인 Unity에서 조작감을 수동 평가한 결과는 아니다. 화면은 해당 별도 플레이 검수에서 저장했다.

### 2026-10-20 일반 공격 1차 조정

열린 VARCO 플로우 `c86e923e-29ea-4e5b-95bf-175bde9c08d9`에서 기존 주인공 리그와 `combo_slash` 결과를 확인했다. 원본을 다시 생성하지 않고 Unity에서 파생 클립을 제작했다. 플로우의 Animate 미리보기는 원본이며, 수정본은 Unity와 아래 비교 캡처에서 확인한다.

| 항목 | 기존 쿼터뷰 데이터 | 3인칭 비교용 가안 |
| --- | --- | --- |
| 각 타격 모션 길이 | 0.74 / 0.72 / 0.80초 | 0.52 / 0.50 / 0.64초 |
| 각 타격 안의 피해 시각 | 0.616 / 0.259 / 0.616초 | 0.270 / 0.200 / 0.330초 |
| 3타 모션 길이 합계 | 2.26초 | 1.66초 |
| 피해·사거리 배율 | 1 / 1 | 1 / 1 |

준비·타격·회수 구간을 단조 시간 곡선으로 재매핑한다. 골반·머리·발·발끝·어깨·팔꿈치 위치 경로를 유지하고 전완은 보존된 VARCO 원본 회전을 사용한다. 손의 월드 회전에서 검 궤적을 연속화한 뒤 손목의 로컬 회전 곡선으로 베이크한다. 타격 부근의 방향과 연격 양 끝 방향을 고정하여 손목 보간 때문에 칼이 표적을 벗어나거나 다음 타수에서 방향이 뛰지 않도록 한다. 별도 IK나 런타임 본 강제 조작을 추가하지 않는다. 정수 그립과 기존 손가락 마스크를 유지한다.

새 데이터는 `Assets/_ERGOSQUARE/08.Data/ThirdPersonComparison/Attacks/`의 `Attack1~3.anim`, `ThirdPerson_AttackSequence.asset`, `ThirdPerson_AnimationSet.asset`, `Architect_ThirdPerson_Combat.controller`다. 비교 씬의 프리팹 인스턴스에 공격 데이터·Visual·Animator 참조 6개만 오버라이드한다. 기존 플레이어 프리팹과 쿼터뷰 씬·공격 자산은 변경하지 않는다. 씬을 다시 생성하는 에디터 빌더도 준비된 전용 프로필을 재사용한다.

재생 전 루트의 `Demo Player Rig`와 실제 모델 Animator에서 새 컨트롤러를 확인한다. Unity 메뉴 `Tools → ERGOSQUARE → Comparison → Open Third Person Attack Animator`로 공격 그래프를 연다. 상태 이름 `Attack1~3`, FSM, 공격 데이터, Animation Event와 기존 예약 입력을 그대로 연결한다.

### 2026-10-21 단타 복귀·쿨타임·필드 배치

기본 공격 원본 클립의 본·검 곡선은 바꾸지 않고 재생률을 1.7배로 조정했다. 1타는 약 1.088초, 2타는 약 1.093초이며 타격 시각은 각 타 안에서 약 0.565초 / 0.165초다. 피해 시각과 Animator의 MotionRate는 같은 공격 데이터를 따른다. 피해·사거리 배율은 유지한다. 수치는 조작감 비교용 가안이다.

다음 타수가 예약되지 않은 공격 종료 시 실제 Animator를 Idle 또는 Move로 0.28초간 블렌딩하고, 모델의 방향 보정도 같은 시간 동안 부드럽게 복귀시킨다. 예약된 1→2타는 중간 복귀를 거치지 않는다. 손가락이나 손목 본을 런타임에서 강제로 덮어쓰지 않는다.

기존에는 기본 쿨타임을 코어의 ReadyAt에 기록하고 그 값을 모든 연결 무기의 쿨타임으로 조회했다. 이제 기본 쿨타임과 해당 사용의 과부하 추가 시간은 사용한 파츠의 InstanceId에 기록한다. 같은 코어의 열·추가 자원 잔량은 공유하지만, 사용하지 않은 다른 무기의 쿨타임은 시작하지 않는다. 연계 추가 사용은 같은 파츠의 과부하 시간을 더한다. 키 재배정·다른 스퀘어로 이동·포트폴리오 복원으로 사용한 파츠의 쿨타임을 초기화할 수 없다. 코어 냉각 중 다른 스퀘어로 코어를 옮기지 못하는 기존 제한은 유지한다.

3인칭 두 씬에는 필드 전개 프레젠터와 월드 격자 연결이 없었고, 새 UI는 Tab 전개 요청을 편집창 열기로 다시 처리했다. 동굴의 연속 바닥도 Default 레이어여서 Ground 레이어만 검사하는 설치 판정이 지면을 찾지 못했다. 두 씬에 전개·격자·지면 참조를 저장하고 비교 씬에서만 DirectFieldPreview를 켰다. 동굴 바닥은 Ground로 지정해 맵 프리팹과 씬에 반영했다. 후속 점프 검수에서 Environment가 현재 프로젝트에 미등록인 점을 확인해 벽·암석은 기존 Default를 사용하고, 설치 장애물 마스크에 Default도 포함했다. 미등록 레이어를 GameObject에 지정하지 않도록 빌더를 보정했다. 이 단계의 Tab 미리보기는 커서를 해제하고 이동·공격·스킬을 차단했으나, 아래 ‘조준점 기반 필드 전개’에서 이동·시점을 유지하는 방식으로 교체했다. 기존 쿼터뷰 입력 경로는 그대로 사용한다. 배치에는 모든 파츠의 점유 칸 아래 바닥과 장애물 검사가 필요하므로 벽 근처에서는 위치를 옮겨야 할 수 있다.

검증 근거는 Unity 저장소 `Tools/ArtReview/Combat_Usability_20261021/`에 기록한다. 별도 Unity의 실제 Input System 이벤트로 검사하며, 사용자의 주 에디터에서 직접 손으로 평가한 조작감과는 구분한다.

최종 동굴 회귀에서도 이동·공격·스킬·UI 검사 15개와 카메라 표본 384개를 통과했다. 결과는 같은 검수 폴더의 `CaveRegression/`에 보관한다. 현재 열려 있는 주 에디터의 재생을 종료하고 수정한 씬을 다시 열어야 저장된 전개 컴포넌트 연결이 새로 로드된다.

### 2026-10-21 Space 점프

3인칭 비교 전용 입력에서 Space를 Jump, 정신 집중을 왼쪽 Ctrl로 분리했다. Shift 달리기·QERTZXCV·F·1234·B/Tab은 기존 역할을 유지한다. 공용 쿼터뷰 입력 자산과 기본 데모 프리팹의 점프 활성화 값은 변경하지 않는다.

Tab 중 마우스 회전과 WASD 이동, 조준에 따른 셀 변경, 청록/빨강 미리보기, 가림·거리·바닥 없음 판정, 0.75m 가장자리 시험 바닥, 4개 파츠 설치와 위치 고정, 코어 생성·수동/거리 회수, 취소와 B/공격 복귀를 확인했다. 기존 숄더뷰 실제 입력 검사 55개와 카메라 표본 1,152개도 다시 통과했다. 시험 블록은 본래 씬에 저장하지 않았으며 주 에디터의 수동 조작감 검수는 포함하지 않는다.

### 2026-10-21 공격 방향 안정화·전개 사유·1m 격자

숄더 카메라의 광선이 몸 바로 앞의 바닥·가림 물체를 잡으면 짧은 전방 거리와 옆 오프셋으로 인해 공격 방향이 거의 옆을 향할 수 있었다. 전방 최소 깊이 1.25m(가안)까지 중앙 광선을 연장하는 방향 계산을 추가한다. 실제 `AimPoint`는 앞쪽 장애물을 계속 반환하므로 벽 뒤 표적을 조준한 것으로 바꾸지 않는다. 플레이어와 장착물의 자식 콜라이더는 중앙 광선에서 제외한다. 클릭 입력 콜백에서는 요청만 저장하고, 같은 프레임의 마우스 회전·카메라 갱신 뒤 공격을 시작한다. 원본 검 2단 베기 클립·타격 시간·피해 횟수는 변경하지 않는다.

전개는 선택 스퀘어뿐 아니라 편성된 모든 스퀘어 파츠를 함께 설치한다. 따라서 선택 격자 아래 바닥이 있어도 화면 밖 다른 파츠가 벽·등불·바위·표적 등에 겹치거나 받침을 벗어나면 실패한다. 일반적인 바닥 오류 대신 실패한 스퀘어 이름·파츠 이름·장애물 종류 또는 전체 점유 영역의 바닥 부족을 표시한다. 모든 스퀘어의 파츠 점유 테두리를 함께 그려 실패한 파츠를 빨간색으로 표시한다. 높이 보정된 전체 점유 영역으로 충돌을 한 번 검사하며, 과거 개별 셀의 더 낮은 표면 높이에서 중복 검사하던 경로를 제거한다. 플레이어 자신의 콜라이더는 설치 장애물에서 제외하지만 실제 외부 장애물과 받침 없는 바닥은 계속 차단한다.

3인칭 비교 두 씬과 빌더의 셀 크기를 2m에서 1m로 조정한다. 가로·세로는 절반, 같은 칸 수의 면적은 1/4이 된다. 격자·조준 스냅·실제 전개·판정이 같은 셀 크기를 사용한다. 실제 파츠와 미리보기는 비율을 유지하여 자신의 논리 점유 영역 안에 들어오도록 축소하고, 메시 중심을 점유 중심에 맞춘다. 세로 높이는 기존 받침 검사와 하단 여백을 유지한다. 원래 쿼터뷰 씬과 기본 프리팹은 변경하지 않는다.

입구 방의 고정된 30개 조준 위치에서 전체 파츠가 설치 가능한 경우는 2m가 3곳, 1.25m가 12곳, 1m가 19곳이었다. 같은 현재 판정 코드에서 크기만 바꾼 비교이며 전체 맵의 성공률이나 최종 밸런스 수치는 아니다. 캡처와 근거는 게임 저장소 `Tools/ArtReview/Combat_Deployment_Polish_20261021/`에 보관한다. 1m는 확장 면적과 파츠 가독성을 함께 확인하기 위한 가안이다.

별도 Unity에서 수정 항목 검사 25개, 1m 전개 회귀 56개, 숄더뷰 회귀 55개를 통과했다. 같은 프레임의 마우스 회전 뒤 첫 타격 이벤트, 두 번의 실제 공격 판정과 127프레임의 실시간 공격 방향, 480개 동굴 시점의 방향 안정성(최대 약 34.23도), 다른 스퀘어의 벽 충돌 사유·빨간 테두리, 받침 없는 장식 바닥 차단, 실제 4개 파츠의 점유 영역 맞춤을 확인했다. 회귀에서는 실제 근접 표적에 2타 합계 30 피해, 이동·점프·메뉴·카메라 충돌 표본 1,152개와 자원 생성·회수도 확인했다. 월도 물건 표현의 필드 전개 옵션은 수직을 유지하는 방향 표시와 축소 비율에 맞는 도깨비불 오프셋을 사용한다. 회전 가능한 최대 수평 폭을 기준으로 축소하고 설치 후 카메라 24방향에서도 점유 영역 안에 있음을 추가 확인했다. 원래 적·스킬용 표현의 기본 동작은 유지한다.

## 남은 문제

마우스 감도·거리·카메라 전환과 각 키의 접근성은 실제 수동 플레이 평가가 필요하다. 현재는 키보드·마우스와 NavMesh 지면·제한된 점프 비교이며 패드·사용자 키 재설정 UI·공중 공격·틈 건너기·회피·록온·소모품 인벤토리 통합·최종 전투 밸런스는 포함하지 않는다. 별도 동굴 공간 프리뷰는 추가했으며, 실제 튜토리얼 진행과 보스 구역 이전·기존 빌드 씬 교체는 후속이다. 벽 반복과 바닥 모듈 경계의 추가 미술 보정, 혼전 중 시야와 모든 벽 근접 위치의 수동 평가, 실제 프레임레이트 측정도 남아 있다.
