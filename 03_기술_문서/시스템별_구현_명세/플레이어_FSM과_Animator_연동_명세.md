# 플레이어 FSM과 Animator 연동 명세

문서 상태: 초안 · 별도 Unity 프로토타입 검수 통과 / 작성자: 송예찬 / 기준일: 2026-10-20

## 목적

3D 플레이어의 실제 이동·장비·공격·스킬·집중·체력 상태를 Unity Animator에 연결한다. 월드 캐릭터의 런타임 `SampleAnimation`과 수동 뼈 보간을 제거하고, 게임플레이 상태가 표현을 결정하게 한다. 인벤토리의 독립 캐릭터 미리보기는 별도 표현 경로를 유지한다.

편집 모드에서도 튜토리얼 플레이어에 FSM과 모델 Animator를 저장하고, 인스펙터에서 실제 참조를 확인한다. 공격은 보존된 VARCO 원래 3타를 사용하며 검 궤적에 필요한 오른쪽 전완·손목 회전만 보정한다.

## 사용자 흐름

이동 명령 → NavMesh 속도와 방향 → Move 상태의 걷기/달리기 블렌드. 무기 드래그 장착 → 오른손 검과 손가락 그립. 평타 입력 → 1타 → 입력 예약 시 2·3타 → 대기. Q 등 배정 스킬 → 실제 실행 시간에 맞춘 공통 시전 동작. 집중 유지 → 집중 자세. 편집창 열기 또는 사망 → 진행 중 동작과 미처리 판정 취소.

재생 전 `Player_Architect_Demo` 프리팹 또는 구역 안의 해당 인스턴스 선택 → 루트의 `Demo Player Rig`에서 이동·전투·인벤토리·스퀘어·FSM·Animator 연결 확인 → `Animator 그래프 열기`로 실제 그래프 열기. 재생 중에는 실제 FSM 상태·공격 단계·속도·클립이 갱신된다. 재생 전 상태는 `편집 모드 · 아직 재생하지 않음`으로 표시한다. Unity 메뉴 `Tools/ERGOSQUARE/Player/Open Demo Player Prefab`에서도 바로 연다.

`Player_Test.prefab`은 테스트 전용으로 보존한다. 현행 데모 캐릭터는 VARCO 모델에서 별도로 만든 일반 프리팹 `Assets/_ERGOSQUARE/03.Prefabs/Gameplay/Player/Player_Architect_Demo.prefab`이며 테스트 프리팹의 변형이나 종속 프리팹이 아니다. 기존 테스트 플레이어의 게임플레이 컴포넌트와 설정을 옮기고 캡슐 표면의 MeshFilter/MeshRenderer는 포함하지 않는다. 물리용 CapsuleCollider는 유지한다.

```text
Player_Architect_Demo    ← 이동·전투·체력·인벤토리·스퀘어·FSM·Demo Player Rig
├─ Visual
│  └─ ArchitectModel    ← 실제 Animator·VARCO 스킨·손의 검
├─ CameraTarget
└─ SkillHandAnchor
```

모델의 방향 보정은 Visual 아래에서 수행하며 플레이어 이동 루트를 돌리지 않는다. 동굴·보스·귀환의 세 조립 프리팹과 본부 씬이 같은 데모 플레이어를 사용한다. 카메라·입력·새 UI·진행기는 새 개체로 다시 연결하며, 이전 구역별 `_Player.prefab`은 현행 구역에서 사용하지 않는 과거 자산이다. `Demo Player Rig`를 Transform 바로 다음에 배치하여 연결 요약이 먼저 보이게 한다.

## 동작 규칙

- `PlayerActionStateMachine`이 상태 우선순위와 요청 가능 여부를 소유한다. 피해, 자원 지불, 쿨타임은 기존 게임플레이 담당 컴포넌트가 소유한다.
- Animator는 FSM의 관찰자이며 이동·피해·스킬 사용 승인을 만들지 않는다. NavMesh가 월드 이동을 소유하고 `applyRootMotion`은 끈다.
- 기본 공격의 모션·길이·타격 비율·입력 예약 구간·피해/범위 배율은 `BasicAttackSequenceDefinition`에서 읽는다. 같은 데이터를 게임플레이 타이머와 Animator 재생 속도에 사용한다.
- 공격 이벤트는 타수·실행 일련번호·미처리 판정을 검사한다. 중복 또는 취소 후 이벤트는 추가 피해를 주지 않는다. 같은 데이터 시각의 게임플레이 타이머도 안전장치로 유지하며, 한 타의 판정은 한 번만 소비한다.
- 메뉴/사망은 평타 예약, 실행 중 스킬 코루틴, 집중을 취소한다. 지불한 자원과 쿨타임은 환불하지 않는다. 사망 시 소환체도 회수한다.
- 이동 명령과 장비 해제의 기존 평타 취소 경로를 유지한다. 일반 장비 피해와 범위 배율은 세 타 모두 1로 유지한다.

## 입력과 출력

| 입력 소유자 | 읽는 데이터 | 출력 |
| --- | --- | --- |
| PlayerNavMotor | 실제 속도와 이동 명령 | Moving, Walk/Run, 이동 방향 회전 |
| PrototypeEquipment | 장착 여부 | 검 표시, 그립 레이어 |
| PrototypeBasicAttack | 타수·일련번호·진행 시간·공격 데이터 | Attack1/2/3, MotionRate, 중복 방지 타격 |
| PrototypeSkillUseController | 실제 CurrentExecution과 Duration | Skill, 실행 중 검 숨김 |
| PlayerFocusController | 실제 IsFocusing | Focus |
| BlueprintEditController | 실제 IsOpen | Menu, 동작 취소 |
| PrototypePlayerHealth | 실제 IsDefeated | Dead, 행동 거부 |

집중 컨트롤러는 입력 오브젝트에 있으므로, 플레이어와 같은 오브젝트라고 가정하지 않고 `ControlledMotor`로 연결한다.

## 상태

우선순위는 Dead → Menu → Skill → Focus → BasicAttack → Moving → Idle이다. 기본 공격 안에서는 Windup → Strike → Recovery를 데이터의 활성 구간으로 구분한다.

실제 Controller의 기본 레이어는 Idle, Move, Attack1, Attack2, Attack3, Skill, Focus, Menu, Dead의 9개 상태다. Move 안의 `Walk_Run_Gait` 1D BlendTree가 Walk/Run 모션을 연속 재생한다. 속도 경계를 넘을 때 별도 Walk/Run 상태로 재진입하지 않는다. 별도 손가락 마스크 레이어는 오른손 15개 손가락 관절만 덮어쓴다. 기본 공격의 하체·몸통·어깨·팔 위치는 VARCO 원본 곡선을 유지하고 오른쪽 전완·손목 회전만 보정한다.

보행은 원본 VARCO Walk의 60–88프레임(24fps, 약 1.167초), Jog의 60–79프레임(약 0.792초)을 사용한다. 두 구간은 왼발 지지/오른발 통과 위상으로 맞추고 자세와 곡선 끝의 속도를 연결한다. 발끝 첫 프레임에서 얻은 서로 다른 방향으로 모델 래퍼를 돌리던 방식을 제거했다. 대신 몸통의 평균 전방 방향을 클립에 베이크하고 Idle/Walk/Run의 기준 방향을 통일한다. 소스의 팔·다리 스윙은 유지하며 스킨 최저점을 기존 바닥 기준으로 보정한다.

`Speed`는 실제 이동 속도, `LocomotionSpeed`는 표현용으로 평활화한 속도다. 평활 시간 0.12초, Idle→Move 전환 0.18초, 복귀 0.16초, Walk/Run 기준 속도 1.6/4.0은 **가안**이다. 이동 속도 자체는 NavMesh 설정을 유지한다. 기준 속도를 바꾸는 경우 BlendTree 임계값과 재생 속도 기준을 함께 맞춰야 한다. `UnifiedLocomotion`은 새 Controller 구조가 준비된 데이터에서만 켜며, 이전 데이터 임포트 중에는 기존 경로를 사용한다. `ActiveClip`은 블렌드 중 가장 비중이 큰 실제 클립을 반환한다.

VARCO 원본은 기존 주인공 리깅 작업 `2ea6db86-7a9d-414f-8da4-5cca21997cbd`에 적용한 `combo_slash`, `gather_hands_magic`, `breathing_stance_looping`, `hit_fall`이다. 검토 후보 `sword_slash`, `double_slash`도 원본과 FBX를 보존한다. Skill/Focus/Dead는 해당 VARCO 클립을 유지한다. 현재 기본 공격은 아래의 로컬 보정 클립을 사용하며 VARCO에서 새로 생성한 모션으로 표시하지 않는다.

v0.2–v0.4에서는 `combo_slash`를 0–1.55초, 1.55–3.15초, 3.15–종료로 잘라 사용했다. 정수 그립을 적용한 뒤 손목과 실제 검날 방향이 맞지 않아, v0.5에서 대각 내려 베기 → 반대 대각 올려 베기 → 정면 내려 베기로 교체했다. 같은 VARCO 리그와 방향·바닥을 맞춘 Idle을 바탕으로, 팔의 2본 IK와 몸통 회전, 전완의 비틀림 분담, 손목 방향을 에디터에서 계산해 90fps Transform 곡선으로 베이크한다. 오른손 회전은 실제 검의 손 기준 부착 회전을 역산하며 검 자식만 표적 쪽으로 따로 돌리지 않는다. 손가락 그립 레이어와 검지·엄지 쪽 정수 그립은 유지한다.

추가 검술 영상의 발 디딤과 체중 이동은 `Sword_Footwork_v6` 모션에 적용했다. 양쪽 다리의 2본 IK로 발 위치와 회전을 베이크하고, 1타에서 앞발을 들어 전방·측면으로 디딘다. 연타 동안 앞발의 디딤 위치를 유지하면서 골반이 낮아지고 좌우로 체중을 옮긴다. 뒷발은 앞부분의 `ToeBase`를 축으로 뒤꿈치를 들고 회전한다. 3타 이후에는 앞발을 들어 원래 자리로 회수한다. 골반 회전이 먼저 시작되고 가슴·팔·검날이 뒤따르며, 목은 공격 방향을 보도록 상체 회전을 일부 상쇄한다. 다리와 골반도 기존 Attack1/2/3 클립의 Transform 곡선이므로 실제 Animator가 함께 재생한다.

골반의 체중 전환 구간 0.22–0.60, 가슴 회전 구간 0.26–0.64, 첫 디딤 구간 0–0.28, 마지막 회수 구간 0.72–1.00은 **가안**이다. 관절의 표현상 이동이며 NavMesh가 소유하는 플레이어 위치에 전진·돌진을 추가하지 않는다. 피해 시점과 검날 평면, 정수 그립, 세 타격의 경계 자세는 같은 기준을 유지한다.

상기 v0.5 및 하체 재구성은 사용자의 원본 동작 보존 요구에 따라 현재 기본 공격에서 제외했다. `PlayerSwordCutAssets`는 실험용 메뉴로 옮겼으며 정상 재생성 경로는 `PlayerSwordTrajectoryAssets`를 사용한다. 보존한 원본 3타를 활성 Attack1/2/3에 복사하고, 오른쪽 `RightForeArm`/`RightHand`의 쿼터니언 8개 채널만 수정한다. 나머지 1,626개 float 곡선은 키·탄젠트·래핑을 포함해 원본과 동일함을 검사한다. 손 위치도 유지하며, 원본 몸 동작을 새로 설계하거나 다리·골반·가슴을 IK로 다시 만들지 않는다.

재생 시간 0.74/0.72/0.80초, 블렌드 0.055초는 유지한다. 타격 진행률도 원본 3타 기준 약 0.8323/0.3594/0.7701로 복원한다. 원본 방향 보정 20.612839도와 입력 예약·피해·범위 값을 유지한다. 목표 쪽 칼날 방향의 보정 회전을 시간 앵커 사이에서 연결하고, 전완에 유한한 축 회전을 나누어 손목을 보정한다. 재생 전환 지연을 포함한 타격 부근의 원본 손 위치에서도 검이 표적을 향하도록 보정 앵커를 둔다. 수치와 조작감은 **가안**이다. 클립은 실제 Animator가 재생하며 런타임 뼈 샘플링을 추가하지 않는다.

기존 광역 구/부채꼴 피해 판정과 피해·사거리 배율 1은 유지한다. 검날과 표적의 겹침 검사는 대표 전방 표적에서 표현과 타격 시점을 확인하는 용도이며, 판정 자체를 메시 충돌 방식으로 바꾸지는 않는다. `BlendSeconds`는 에셋 빌드 시 Controller 전환에 반영되므로 변경 후 빌드가 필요하다. Duration·Motion·피해 배율은 런타임 공격 데이터에서 읽는다. 전체 플레이어 애니메이션 재생성 메뉴도 보행 빌드 다음에 원본 보존형 검 궤적 보정을 실행한다.

### 커스터마이징을 위한 외형 교체 계약

다음은 후속 구현 기준이다. 현재 `Player_Architect_Demo.prefab`의 캐릭터 스킨은 `ArchitectBody`의 `SkinnedMeshRenderer` 하나이며, 교체용 기본 신체·의상 슬롯과 외형 교체 기능은 아직 없다. 현재 외형은 데모용으로 유지하고 새로운 의상을 제작할 때부터 아래 기준을 적용한다.

- **플레이어 루트 유지:** 이동·물리·전투·체력·인벤토리·스퀘어·FSM은 기존 루트가 소유한다. 외형 교체는 `Visual` 아래의 표현만 변경하며 카메라 대상과 스킬 기준점, 실행 중 전투 상태를 재생성하지 않는다. `Demo Player Rig`에서 FSM과 실제 Animator 연결을 재생 전에도 계속 확인할 수 있어야 한다.
- **공통 골격과 Animator:** 기본 신체와 의상은 하나의 기준 골격을 공유하도록 제작한다. 의상 스킨의 본 참조·바인드 포즈·웨이트를 기준 골격에 맞추고, 현재 모션이 참조하는 뼈 이름과 계층 경로를 보존한다. 의상마다 별도 Animator를 구동하지 않는다. 모델 방향 보정은 기존 Visual 래퍼에 유지한다.
- **별도 기본 신체와 의상:** 의상이 없는 기본 신체, 머리카락, 상·하의, 신발 등 교체 단위의 메시를 준비한다. 슬롯 분류는 가안이다. 현재 옷 입은 메시의 표시를 끄는 것만으로 기본 신체가 만들어지는 것으로 취급하지 않는다. VARCO에서 개별 생성한 의상도 체형 맞춤·리토폴로지·스키닝과 기준 골격 호환 검수를 거쳐야 한다.
- **피부 노출과 체형:** 옷에 가려지는 신체 영역을 숨기는 방식과 의상별 노출 범위를 정의하여 피부 관통을 줄인다. 체형 변경을 지원할 경우 의상에도 대응하는 변형을 준비한다. 장발·긴 옷의 물리 및 체형 편집 범위는 후속 결정이다.
- **외형 데이터와 표현 갱신:** 기본 신체·부위별 외형 ID·색상 등의 외형 데이터를 능력치와 장비 소유 데이터에서 분리한다. 외형 변경 시 월드와 인벤토리 미리보기가 같은 데이터를 반영하도록 한다. 현재 `InventoryCharacterPreview`는 모델 복제본을 캐시하므로 외형 변경 이벤트 또는 버전으로 갱신해야 한다. 새 렌더러의 윤곽선·재질·미리보기 프레이밍도 갱신한다. 외형 저장 데이터 형식은 아직 미정이다.
- **무기와 애니메이션 보존:** 손의 무기 소켓·정수 그립·현재 Animator Controller와 공격 데이터를 유지한다. 외형 교체가 장비 소유권이나 타격 권한을 바꾸지 않는다. 다른 골격으로 교체하는 기능은 별도 리타기팅과 참조 재연결 검수 범위로 둔다.

첫 교체 기능의 완료 조건은 상의 한 벌을 교체한 뒤 재생 전 FSM/Animator 참조가 유지되고, 쿼터뷰의 정지·이동·3단 공격에서 신체 관통과 스킨 변형을 확인하며, 월드와 인벤토리 미리보기의 외형이 일치하는 것이다. 장비·체력·스퀘어 상태와 구역 전환 후 외형 유지도 함께 검수한다. 이는 후속 수용 기준이며 기존 데모 검수 결과에 포함하지 않는다.

## 예외 처리

- 취소된 공격의 잔여 이벤트는 타격 권한을 복원하지 않는다.
- 적이 여러 콜라이더를 가져도 동일 피해 수신기에 한 번만 적용한다.
- 3D 검이 준비되면 구형 장비 표시기의 임시 막대 검을 켜지 않는다.
- 검은 `SwordGripPose`에서 정수 그립으로 정렬한다. 손바닥의 법선 방향을 검날 방향으로 쓰지 않고 검지/소지 관절의 기부를 기준으로 검날이 검지·엄지 쪽으로 나오게 한다. 손잡이 위치와 손가락 그립은 유지한다. 월드 모델 초기화, 인벤토리 미리보기 재바인딩, 주인공 프리팹에 같은 기준을 적용한다. 이 부착 보정과 별도로 기본 공격 클립은 원본 몸 동작을 유지하고 오른쪽 전완·손목 회전만 보정한다.
- 구형 `Animation`과 새 `Animator`가 동일 모델에서 경쟁하지 않게 구형 컴포넌트를 제거한다.
- 사망·메뉴에서는 스킬 실행 코루틴까지 중단해 표현만 멈추고 피해가 나중에 발생하는 상황을 막는다.

## UI·피드백

신규 3열 인벤토리와 드래그 장착을 유지한다. 장비 상태가 월드의 손에 든 검과 그립으로 연결된다. 인벤토리 미리보기는 복제 모델을 사용하며 월드 Animator의 상태나 게임플레이 판정을 바꾸지 않는다.

두 튜토리얼 씬에는 플레이어 FSM·장비·공격 컴포넌트, `ArchitectModel`의 Animator, 실제 Controller·공격 데이터 참조를 편집 모드로 저장한다. `TutorialPlayer3DVisual`은 직렬화된 데이터·FSM·Animator를 우선 사용한다. FSM은 모델 Animator에 대한 진단용 참조를 노출하며 게임플레이 승인 권한은 기존대로 유지한다. 순서가 있는 `Start`에서 런타임 의존성을 다시 바인딩한다.

전용 인스펙터는 연결 상태, 현재 상태와 공격 단계, 속도, 재생 클립, 사용 중 공격 데이터와 보존 원본을 표시한다. `Animator 그래프 열기`, `연결된 모델 선택`, 편집 모드의 `연결 복구` 버튼을 제공한다. 레거시 참조는 호환용 접힌 항목으로 구분한다. 연결 보정기는 스크립트 리로드·씬 열기 때 비어 있는 참조를 보완하고 열린 씬을 dirty로 표시하지만 사용자의 열린 씬을 자동 저장하지 않는다. 기존 사용자 지정 Controller는 임의로 덮어쓰지 않고 불일치를 인스펙터에 표시한다.

독립 데모 프리팹 이관은 `Tools/ArtReview/Demo_Player_VARCO_20261018`에서 별도 검수했다. 생성·자산 분리·참조 이관 27개, 최종 편집/빌드 의존성 25개를 통과했으며 활성 빌드 씬 7개 모두 `Player_Test` 의존성이 없다. 실제 새 데모 플레이어로 튜토리얼·보스·귀환 진행 72개, 장비 드래그/UI 17개, Animator·공격 210개, 에르고 스퀘어·소환·본부 인계 80개를 통과했다. 반복 프레임 검사를 포함한다. 테스트 프리팹과 메타 파일은 바이트 단위로 보존하고 원래 모션·Controller·데이터 파일도 변경하지 않았다. 메인 Unity 창의 미저장 씬은 자동 저장하거나 폐기하지 않는다.

### 3인칭 비교용 파생 공격 · 2026-10-20

쿼터뷰의 원본 컨트롤러와 데모 프리팹은 유지한다. 3인칭 비교 씬은 별도 `ThirdPersonComparison/Attacks`의 Animation Set·Attack Sequence·Animator Controller를 참조하며 재생 전 실제 Animator 그래프에도 해당 파생 3타가 연결된다. 원본의 몸·발 경로를 재매핑하고 검의 월드 회전을 연속화하여 베이크한 클립이다. 런타임의 상태 소유자와 피해 소유자는 기존 FSM·`PrototypeBasicAttack`이며, 타격 이벤트·타이머·입력 예약 계약은 바뀌지 않는다.

설정 시간·자산 목록·정지 표적 근접 검사와 자동 플레이 결과는 [3인칭 비교 씬 명세](3인칭_비교씬_조작과_검수_명세.md#2026-10-20-일반-공격-1차-조정)를 따른다. Unity 메뉴 `Tools → ERGOSQUARE → Comparison → Open Third Person Attack Animator`로 전용 그래프를 연다.

## 남은 문제

- 추가 동작 참고: [검술 기본베기 · Basic sword strikes.](https://www.youtube.com/shorts/23zEqmgEkB0). 영상의 발 디딤, 굽힌 무릎과 체중 이동, 골반·어깨 회전, 여러 베기 방향의 연결을 확인했다. 양손 검술 시범이므로 주인공의 한손 정수 그립에 맞춰 해석한다. 앞서 제공된 [한손검 두 번째 공격 모션](https://www.youtube.com/watch?v=MVE6-G9L3pU)은 한손 자세와 공격 실루엣의 참고로 함께 유지한다.
- 추가 영상에서 착안한 통째 재구성 모션은 현재 기본 공격에서 제외했다. 원본 몸 동작을 보존하는 것이 현재 기준이며, 추가적인 몸 동작 변경은 별도 요청 범위로 다룬다.
- 모든 무기·스킬에 고유한 시전 동작을 주는 작업은 후속이다. 현재 Skill은 실제 실행 시간에 동기화한 공통 VARCO 동작이다.
- 경사면 발 IK와 모든 방향·모든 적을 상대로 한 수동 조작감 검수는 포함하지 않는다.
- 메인 에디터의 미저장 씬은 덮어쓰지 않는다. 별도 프로젝트 검수가 메인 에디터의 최신 임포트·컴파일을 증명하지 않는다.
