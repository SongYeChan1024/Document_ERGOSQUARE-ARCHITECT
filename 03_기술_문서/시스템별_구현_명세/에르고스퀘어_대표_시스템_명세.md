# 에르고스퀘어 대표 시스템 명세

> [!IMPORTANT]
> 문서 상태: 초안. 시간과 수치는 프로토타입 검증 전 가안입니다.

## 1. 목적

인벤토리에서 만든 청사진을 실제 전투 공간으로 전환해, 빌드 설계와 액션 전투를 하나의 경험으로 연결합니다.

## 2. 사용자 흐름

```text
프레임 선택 → 코어·모듈 배치 → 유효성 검사 → 청사진 저장
→ 전개 위치 지정 → 전개 → 설치 → 모듈 활성화 → 방어 또는 회수
```

`전개`는 인벤토리 게이트를 열어 청사진의 격자를 현실 공간에 펼치는 단계입니다. `설치`는 배치된 모듈이 홀로그램 상태에서 실체화되어 기능을 활성화하는 단계입니다. 전개된 청사진은 위치와 방향에 고정되며 플레이어를 따라다니지 않습니다.

## 3. 동작 규칙

- 시작 조건: 유효한 코어와 프레임이 포함된 청사진 보유
- 실행 조건: 전개 가능한 지면, 공간, 상태 충족
- 성공 조건: 모든 유효 모듈이 월드에 생성되고 기능 활성화
- 실패 조건: 공간 충돌, 금지 구역, 자원 부족, 상태 불일치
- 종료 조건: 회수 완료, 코어 파괴 또는 작전 종료
- 전개 가안: 1초
- 전개 후 회수 가능 시간 가안: 10초
- 회수 가안: 2초
- 회수 후 재전개 대기 가안: 8초

전개된 모든 모듈은 충돌과 피격 판정을 가진 실체입니다. 엄폐물과 방패로 사용할 수 있으나 내구도가 소진되면 파괴됩니다. 핵심 코어가 파괴되면 신규 자원 생성이 중단되며, 이미 축적한 자원의 유지 범위는 `TBD`입니다.

## 4. 입력과 출력

| 입력 | 처리 | 결과 |
| --- | --- | --- |
| 청사진 데이터 | 연결·범위 유효성 검사 | 배치 가능 여부 |
| 전개 입력 | 위치·충돌·상태 검사 | 프리뷰 표시 |
| 확정 입력 | 모듈 월드 좌표 계산 | 에르고스퀘어 생성 |
| 회수 입력 | 전투·피격·시간 검사 | 회수 또는 거절 |
| 적 공격 | 대상 모듈 피해 계산 | 체력 감소·기능 중단 |

## 5. 상태

```text
Editing → Validated → Preview → Deploying → Active
Active → Recalling → Stored
Active → Destroyed
Preview → Cancelled
```

## 6. 데이터

| 변수 | 형식 | 설명 | 기본값 |
| --- | --- | --- | ---: |
| CellSize | float | 격자 한 칸 크기(m) | 1.0 |
| DeployDuration | float | 전개 시간(초) | 1.0 |
| RecallDuration | float | 회수 시간(초) | 2.0 |
| RecallLockDuration | float | 전개 후 회수 제한(초) | 10.0 |
| RedeployCooldown | float | 회수 후 재전개 대기(초) | 8.0 |
| ModuleId | string | 모듈 식별자 | TBD |
| GridPosition | Vector2Int | 청사진 격자 좌표 | (0,0) |
| CurrentHealth | float | 현재 내구도 | 모듈별 |

## 7. 예외 처리

- 전개 공간에 다른 오브젝트가 있을 때 거절하고 원인을 표시합니다.
- 전개 중 취소되면 생성된 임시 오브젝트를 정리합니다.
- 설치 중인 모듈도 공격과 파괴의 영향을 받습니다.
- 코어가 파괴되면 신규 자원 생성을 중단합니다. 잔여 자원을 사용하는 연결 모듈의 종료 시점은 `TBD`입니다.
- 플레이어 사망·이탈 시 소유권과 유지 규칙은 `TBD`입니다.
- 씬 전환 시 활성 인스턴스를 정리하고 보존 데이터만 저장합니다.
- 네트워크 상태가 다르면 권한 보유자의 결과를 기준으로 재동기화합니다.

## 11. 네트워크 대응 원칙

- 청사진 배치 정보는 전개 시점에 묶어서 전송합니다.
- 전개 이후에는 피해·파괴·회수와 같은 상태 변화만 이벤트로 동기화합니다.
- 침식체 AI 권한은 권한 보유 클라이언트 중심 처리를 우선 검토합니다.
- 중도 이탈과 권한 이전 시 코어·모듈 소유권을 다시 결정합니다.
