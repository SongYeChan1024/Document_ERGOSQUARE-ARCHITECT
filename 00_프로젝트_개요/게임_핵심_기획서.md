# 게임 핵심 기획서

> [!IMPORTANT]
> 문서 상태: 초안

## 게임의 목표

팀원과 함께 균열 봉쇄 작전을 수행하고, 전개한 코어를 보호하며 침식체를 제거한 뒤 보상을 회수합니다.

## 승리와 실패

| 구분 | 조건 |
| --- | --- |
| 승리 | 작전 목표 달성 후 결과 단계 진입 |
| 실패 | 팀 전멸 또는 핵심 작전 실패 |
| 부분 손실 | 모듈 파괴로 연결된 기능이나 자원 생산 중단 |

세부 부활·철수 규칙은 프로토타입 이후 확정합니다.

## 플레이어의 핵심 행동

- 청사진 프레임과 모듈 선택
- 격자 기반 모듈 배치
- 에르고스퀘어 전개와 회수
- 이동, 회피, 공격, 상호작용
- 코어와 팀원 보호
- 보상 선택과 다음 빌드 수정

## 조작 방법

키보드·마우스와 게임패드를 목표로 하며 세부 키 배치는 `TBD`입니다.

## 핵심 플레이 루프

자세한 흐름은 [핵심 플레이 루프](../01_게임_기획/핵심_플레이_루프.md)를 기준으로 합니다.

```text
준비 → 편성 → 진입 → 전개 → 전투 → 보상 → 성장 → 재도전
```

## 전투 구조

- 설계자는 직접 이동하고 공격합니다.
- 전개된 모듈은 무기·방어·자원·지원 기능을 제공합니다.
- 침식체는 플레이어뿐 아니라 코어와 모듈을 우선 공격할 수 있습니다.
- 플레이어는 화력 집중과 코어 방어 사이에서 우선순위를 판단합니다.

## 성장 방식

- 작전 중: 획득한 자원으로 임시 강화 또는 모듈 운용
- 작전 사이: 프레임·모듈 선택지와 청사진 개선
- 영구 성장의 범위와 실패 시 보존 규칙은 `TBD`

## 아이템과 보상

자원, 모듈, 무기, 설계 데이터가 후보입니다. 현재 MVP는 코어 시스템 검증에 필요한 최소 보상만 사용합니다.

## 콘텐츠 진행

작전 허브에서 준비하고 균열 지역에 진입합니다. 목표를 달성하면 결과를 분석하고 청사진을 수정해 다음 작전에 도전합니다.

## 난이도 변화

- 적의 수와 조합
- 코어를 압박하는 공격 빈도
- 공간 제약과 작전 목표
- 팀 인원과 청사진 조합

정량 곡선은 플레이테스트 데이터 확보 후 작성합니다.

## 저장과 재시작

- 청사진과 해금 정보의 로컬 저장을 우선 검토합니다.
- 멀티플레이 권한과 중도 이탈 복구 방식은 기술 검증 후 확정합니다.
- 실패 시 허브로 복귀해 청사진을 수정하고 재도전합니다.

## 예상 플레이 시간

MVP 목표는 한 세션 10~15분입니다. 정식 목표 시간은 테스트 결과에 따라 조정합니다.

## 차별점

인벤토리 최적화, 공간 배치, 액션 전투가 분리되지 않고 하나의 위험·보상 구조로 연결됩니다.

## 범위

| MVP | 정식 버전 후보 |
| --- | --- |
| 테스트 전장 1개 | 복수 지역과 작전 유형 |
| 적 1종 이상 | 역할이 다른 적과 보스 |
| 최소 프레임·모듈 | 다양한 설계자 빌드 |
| 기본 결과·재시작 | 장기 성장과 경제 |
