# 프로젝트 로드맵

> [!IMPORTANT]
> 문서 상태: 초안. 일정이 아니라 플레이 가능한 결과를 기준으로 관리합니다.

## P0 — 기술 검증

- 캐릭터 이동과 카메라
- 기본 공격
- 테스트 적
- 격자 배치와 월드 전개

완료 기준: 테스트 공간에서 이동·전투하고 청사진 한 세트를 전개할 수 있습니다.

## P1 — 코어 루프

- 번호 지구 생성·불러오기와 로컬 저장
- 기본 탐색·채집과 임시 기지
- 게이트 발견·진입
- 청사진 편성
- 전개와 회수
- 파츠 피해와 파괴
- 전투·퀘스트 목표, 폐쇄, 귀환과 재도전

완료 기준: 혼자 월드를 생성하고 기지를 만든 뒤 첫 게이트를 닫고 진행 상태를 저장할 수 있습니다.

## P2 — 협동과 콘텐츠

- 최대 4인 호스트 접속과 월드·파츠 상태 동기화
- 적 종류 추가
- 두 번째 게이트 목표와 테스트 지역 제작
- 보상과 성장
- UI와 사운드

완료 기준: 같은 번호 지구에서 혼자 또는 친구와 10~15분 게이트 원정을 완료하고 다시 접속해 진행을 이어갈 수 있습니다.

## P3 — 폴리싱

- 최적화
- 튜토리얼
- 전투·UI 연출
- 버그 수정
- 빌드 배포

완료 기준: 처음 접한 사용자가 별도 설명 없이 핵심 루프를 완료할 수 있습니다.

## 범위 통제

- 각 단계의 완료 기준을 통과하기 전 다음 단계 기능을 확장하지 않습니다.
- 신규 아이디어는 Issues 또는 아이디어 백로그에 기록하고 즉시 범위에 넣지 않습니다.
- 생성형 AI와 라이브 서비스 경제는 MVP 필수 범위에서 제외합니다.

## 주요 리스크와 대응

| 리스크 | 대응 |
| --- | --- |
| 청사진·전투·네트워크 동시 구현으로 범위 증가 | MVP 프레임과 파츠 수 제한 |
| 파츠 단위 지속 동기화로 네트워크 부하 증가 | 전개 정보는 묶어서 전송하고 상태 변화만 이벤트 동기화 |
| 문화권·권능 융합 조합 수의 폭발 | 공통 태그 조합과 선별된 전용 융합 설계를 병행하고 튜토리얼은 단일 계통만 검증 |
| 생성형 AI 응답 실패가 진행을 차단 | 규칙 기반 기본 응답 제공, 생성형 AI는 보조로 제한 |
| 샌드박스·건설·게이트 콘텐츠를 동시에 확장 | MVP 기지는 기능성 오브젝트 중심, 게이트 1개와 싱글 루프 우선 |
| 다른 지구 간 아이템 반입으로 복제·밸런스 붕괴 | MVP는 월드 귀속 저장, 이동 규칙은 엔드게임 이후 검토 |
| 기획 수치가 구현 결과와 혼재 | 기획 가안과 프로토타입 측정값을 분리 기록 |
