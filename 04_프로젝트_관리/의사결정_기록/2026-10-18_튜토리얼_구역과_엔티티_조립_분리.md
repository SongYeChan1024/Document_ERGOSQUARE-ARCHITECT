# 튜토리얼 구역과 엔티티 조립 분리

문서 상태: 초안 · 별도 Unity 검수 / 작성자: 송예찬 / 날짜: 2026-10-18

## 상황

진행기가 맵 확장·조명·적·보상·NavMesh 생성까지 맡고 있었다. 사용자는 루시드 다이버처럼 맵과 엔티티를 나누어 불러오면서 기존 튜토리얼·신규 UI·다중 스퀘어·Play 전 FSM/Animator 확인을 유지하도록 요청했다.

## 선택

플레이어 연결 → 몬스터/조우 → 맵/진행 책임 → 구역 로더 순으로 분리한다. 동굴·보스·귀환은 기존 씬 이름과 렌더 설정을 유지하고 설정을 읽는 로더만 저장한다. Map·Player·Monsters·UI·Systems·Progression 프리팹과 실제 참조는 구역 조립 프리팹에 저장한다. 편집용 미리보기는 저장·빌드에서 제외하고 실제 수정은 조립 프리팹에서 저장한다.

연습 조우는 맵 앵커와 독립 개체 설정을 사용하고 NavMesh는 편집 단계에 베이크한다. 진행기는 학습 순서와 이벤트만 담당한다. 기존 비동기 씬 전환과 메모리 세션 인계를 유지한다.

## 대안과 선택 이유

2026-10-19 추가 방향: 데모 플레이어는 향후 커스터마이징의 시작점으로 사용한다. 안정적인 게임플레이 루트와 Visual 표현의 경계를 유지하고, 의상을 포함하지 않은 기본 신체와 교체 의상을 공통 골격에 연결하는 구조로 확장한다. 의상 교체 때문에 플레이어 전체를 다시 생성하거나 FSM을 초기화하지 않는다. 현재 단일 캐릭터 스킨을 임시 외형으로 사용하며 기본 신체·분리 의상·교체 UI는 후속 제작이다. 외형 데이터와 인벤토리 미리보기 갱신 계약은 [플레이어 연동 명세](../../03_기술_문서/시스템별_구현_명세/플레이어_FSM과_Animator_연동_명세.md#커스터마이징을-위한-외형-교체-계약)에 기록한다.

루시드 다이버의 Additive 씬·전역 SpawnManager·태그 검색을 그대로 옮기는 대신, 현재 UI·장비·스퀘어의 참조를 직렬화한 조립 프리팹에서 보존한다. 향후 큰 월드의 청크 스트리밍은 별도 로딩·해제 정책으로 다룬다. 프리팹 분리만으로 FPS나 메모리 개선율을 확정하지 않는다.

## 결과

2026-10-19에 데모 플레이어를 `Player_Test`에 VARCO 외형을 덧붙이는 형태에서 분리했다. `Player_Architect_Demo.prefab`은 VARCO 모델을 기반으로 독립 생성한 일반 프리팹이며, 이동·전투·체력·장비·자원·인벤토리·에르고 스퀘어·FSM 컴포넌트를 루트에 이관한다. 모델의 Animator는 루트의 `Demo Player Rig` 인스펙터에서 바로 확인한다. 테스트 프리팹은 변경하지 않고 동굴·보스·귀환과 본부가 같은 데모 플레이어를 사용한다.

세 구역 이전 52개·최종 편집 참조 33개·실제 튜토리얼과 구역 이동 66개를 별도 Unity에서 통과했다. 드래그 장착 17개·스퀘어/조합/소환/본부 인계 78개·Animator/전투 210개 회귀도 통과했다. 프레임 반복 검사가 포함되며 수동 완주를 의미하지 않는다. 경로와 범위는 [구역 조립 명세](../../03_기술_문서/시스템별_구현_명세/튜토리얼_구역_조립과_프리팹_분리_명세.md)를 따른다. 메인 에디터 미저장 씬은 자동 저장하거나 폐기하지 않는다.
