# 2026-08-19 개발 일지

## 오늘의 목표

- 플레이어가 상호작용할 수 있는 오브젝트를 즉시 알아볼 수 있도록 `G` 키 안내를 게임 화면에 표시합니다.
- 전날 구현한 빗자루 스킬의 피해·경직·넉백을 실제 대상으로 확인할 수 있는 반복 가능한 전투 샌드박스를 만듭니다.
- 테스트용 오브젝트와 UI를 기능별로 분리해 이후 획득품·조사물·NPC와 적에게 재사용할 수 있게 합니다.

## 작업 내용

### 공통 상호작용 경계

- 상호작용 문구, 우선순위, 사용 가능 상태, 안내 표시 위치와 실행 메서드를 제공하는 `IInteractable` 인터페이스를 정의했습니다.
- 플레이어 주변의 후보를 탐색하고 우선순위와 거리를 비교해 현재 상호작용 대상을 선택하는 `PlayerInteractionController`를 추가했습니다.
- 현재 대상이 바뀔 때 프레젠테이션 계층이 구독할 수 있는 이벤트를 제공했습니다.
- 일회성 조사나 간단한 이벤트에 재사용할 수 있는 프로토타입 상호작용 컴포넌트를 추가했습니다.
- 기존 빗자루 획득 컴포넌트를 공통 인터페이스에 연결해 별도 예외 흐름 없이 `G` 입력으로 획득되도록 정리했습니다.

### 월드 상호작용 안내

- 현재 대상의 월드 좌표를 화면 좌표로 변환해 `G` 키와 행동 문구를 대상 위에 표시하는 Canvas 프레젠터를 구현했습니다.
- 화면 가장자리 여백과 안내 크기를 설정값으로 분리했습니다.
- HUD 프리팹 생성 과정에서 상호작용 프레젠터가 항상 포함되도록 에디터 빌더를 갱신했습니다.
- 플레이 중 씬 오브젝트를 임의로 추가하는 부트스트랩을 제거해, 씬 리로드 비활성 설정에서도 편집 씬이 오염될 가능성을 줄였습니다.

### 타격 데이터와 스킬 차별화

- 피해량뿐 아니라 경직 시간, 넉백 방향·거리와 공격 원점을 함께 전달하는 `PrototypeHitData`를 추가했습니다.
- 피해 수신 컴포넌트가 최대 체력, 현재 체력, 타격 이벤트, 처치와 체력 초기화를 제공하도록 확장했습니다.
- 빗자루 스킬 세 종류에 프로토타입 가안을 적용했습니다.

| 스킬 | 피해 배율 | 경직 | 넉백 | 검증 의도 |
| --- | ---: | ---: | ---: | --- |
| 내려치기 | 1.35 | 0.65초 | 0.35 | 높은 피해와 긴 경직 |
| 쓸어치기 | 1.00 | 0.40초 | 1.40 | 공간 확보와 밀어내기 |
| 찌르기 | 1.15 | 0.25초 | 0.75 | 중간 피해와 직선 압박 |

> [!NOTE]
> 위 수치는 기능 차이를 확인하기 위한 가안이며 플레이테스트 후 조정합니다.

### 테스트용 빗자루 도깨비

- 체력 60의 고정형 테스트 적 프리팹을 제작했습니다.
- 타격을 받으면 경직 상태와 넉백 이동을 처리하고, 체력이 모두 소진되면 비활성 연출 후 2.5초 뒤 원래 위치에서 재생성되도록 했습니다.
- 적 머리 위의 월드 체력바, 피격 점멸, 처치 시 축소와 재생성 시 복원 연출을 별도 프레젠터로 분리했습니다.
- 간단한 원시 메시와 전용 머티리얼로 빗자루 도깨비를 식별할 수 있는 임시 외형을 구성했습니다.
- 전투 표적 프리팹 생성, HUD 상호작용 안내 보강과 `TestMap` 배치를 한 번에 수행하는 전투 샌드박스 빌더를 추가했습니다.

## 발생한 문제

- 시각 피드백 컴포넌트가 필드 초기화 시점에 `MaterialPropertyBlock`을 생성해 Unity 객체 생명주기 예외가 발생했습니다.
- 생성 머티리얼의 초기 경로가 현재 프로젝트의 `04.Graphics` 규칙과 다른 `04.Art` 아래를 가리켰습니다.
- Unity가 열린 상태에서 머티리얼 파일을 외부 이동하자 AssetDatabase가 이전 경로를 기억해 파일 이동 실패 창을 반복 표시했습니다.
- 씬 리로드를 비활성화한 플레이 모드에서 런타임 부트스트랩이 HUD에 컴포넌트를 추가하면 플레이 종료 뒤 씬이 변경된 것으로 남을 수 있었습니다.

## 원인

- `MaterialPropertyBlock`은 Unity 엔진 객체이므로 MonoBehaviour 필드 선언 시점이 아니라 Unity 생명주기 안에서 생성해야 합니다.
- 전투 샌드박스 빌더의 머티리얼 폴더 상수가 기존 그래픽 자산 규칙을 따르지 않았습니다.
- 열린 Unity Editor의 AssetDatabase 상태와 외부 파일 시스템 변경 순서가 일치하지 않았습니다.
- 런타임 탐색 편의를 위해 추가한 자동 부트스트랩이 씬 리로드 비활성 환경의 상태 유지 특성과 충돌했습니다.

## 해결

- `MaterialPropertyBlock` 생성을 `Awake`로 옮기고, 사용 시점에도 누락 여부를 방어적으로 확인했습니다.
- 머티리얼 생성 경로를 `04.Graphics/Common/Materials/Prototype`으로 통일했습니다.
- 파일 이동 실패 작업을 취소하고 Unity의 도메인·에셋 새로고침을 완료한 뒤 빌더를 새 경로에서 다시 실행했습니다.
- 월드 상호작용 프레젠터를 HUD 프리팹과 에디터 빌더가 명시적으로 구성하도록 변경하고 런타임 자동 추가 코드를 제거했습니다.
- 검증 후 전투 샌드박스 빌더를 다시 실행해 플레이 모드의 임시 상태가 편집 씬에 남지 않도록 복원했습니다.

## 검증

- Unity 스크립트 컴파일과 어셈블리 재로드를 통과했습니다.
- `TestMap`에 테스트 적 프리팹이 배치되고 최대 체력 60, 재생성 대기 2.5초 설정이 연결된 것을 확인했습니다.
- 플레이 모드에서 테스트 적의 월드 체력바가 표시되는 것을 확인했습니다.
- 플레이 모드 콘솔에서 컴파일 오류, Null 예외와 경고가 0건임을 확인했습니다.
- 적 프리팹이 몸체·천·눈 머티리얼을 새 그래픽 폴더에서 참조하는 것을 확인했습니다.
- HUD 프리팹이 월드 상호작용 안내 프레젠터를 포함하고 있음을 확인했습니다.
- 실제 입력으로 세 스킬을 반복 사용한 수치 비교와 전투 손맛은 아직 QA 완료로 판정하지 않았습니다.

## 오늘의 결과

- 상호작용 가능한 오브젝트를 탐색하고 화면에 `G` 안내를 표시한 뒤 실행하는 공통 흐름이 생겼습니다.
- 빗자루 스킬의 공격 특성을 비교할 수 있는 재생성형 테스트 적과 시각 피드백이 준비되었습니다.
- 획득·상호작용, 타격 판정, 적 반응과 표현이 각각 교체 가능한 컴포넌트 경계로 분리되었습니다.
- 다음 단계에서 적 AI와 짧은 전투 조우를 구현할 수 있는 최소 전투 샌드박스가 마련되었습니다.

## 다음 작업

1. `G 획득 → 청사진 배치 → 스킬 할당 → 정신 집중 → 적 타격`을 한 세션에서 반복 QA합니다.
2. 플레이어와 코어에 서로 다른 어그로 값을 부여하고 거리·누적 행동에 따라 목표를 바꾸는 적 AI를 구현합니다.
3. 적의 추적, 공격 준비, 공격 판정과 회복 상태를 상태 머신으로 분리합니다.
4. 빗자루 스킬을 Animator와 Animation Event에 연결하고 타격 시점과 시각 연출을 일치시킵니다.
5. 테스트 수치를 바탕으로 첫 도깨비 전투 조우의 적 수, 공간과 완료 조건을 정합니다.
