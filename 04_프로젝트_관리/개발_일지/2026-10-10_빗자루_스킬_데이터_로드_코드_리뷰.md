## 오늘의 목표

빗자루 스킬의 수치가 어디서 들어오는지 이해하기 위해 `DokkaebiGrowthDatabase.Load()`와 `DokkaebiGrowth.json`을 함께 읽습니다. 엑셀에서 정의한 값이 게임에서 사용할 데이터로 바뀌는 과정과 전투 상태 관리의 차이를 정리합니다.

## 코드 리뷰 내용

### 데이터 입력 경로

게임은 실행 중에 엑셀 파일을 직접 읽지 않습니다. 엑셀에서 정한 수치를 변환 도구로 JSON으로 만든 뒤, Unity가 `Assets/_ERGOSQUARE/Resources/Data/DokkaebiGrowth.json`을 읽습니다.

게임 저장소의 `Assets/_ERGOSQUARE/02.Scripts/Gameplay/Runtime/Items/DokkaebiGrowthDatabase.cs`에서 다음 흐름을 살펴봤습니다.

1. `Resources.Load<TextAsset>("Data/DokkaebiGrowth")`로 JSON 파일을 텍스트 에셋으로 불러옵니다.
2. `JsonUtility.FromJson<Tables>(asset.text)`로 JSON 텍스트를 `Tables` 데이터 구조로 변환합니다.
3. 데이터 구조와 값의 검증을 통과하면 `tables = data`로 보관합니다.
4. `Stage()`와 `Action()` 등의 조회 함수가 다른 클래스에 필요한 데이터를 제공합니다.

### 조합 단계와 타격 수치

| 데이터 | 담는 정보 | 리뷰 예시 |
| --- | --- | --- |
| `stages` | 조합 단계별 해금 타수·공유 쿨타임·연계 유예 시간 | `BROOM_3`의 `comboCount=3`은 최대 3타 해금 정보 |
| `actions` | 각 타격의 피해량·소모 자원·돌진 거리·모션 | 1타의 `dashDistance=1.4`는 해당 동작의 기본 이동 거리 |
| `recipes` | 조합 단계와 재료 | 단계 확장에 필요한 조합 정보 |
| `enhancements` | 강화 조건과 효과 | 피해·쿨타임·자원 비용 강화 데이터 |
| `branches` | 진화 분기 조건과 배율 | 다른 형태로 확장하기 위한 분기 데이터 |

현재 JSON의 기본 쿨타임 10초와 연계 유예 6초는 기존 수치의 예시로 확인했으며, 이번 리뷰에서 변경하지 않았습니다.

### 반복 로드와 실패 처리

`attempted`는 같은 실행 세션에서 파일을 반복해서 읽지 않도록 하는 표시입니다. 조회 함수가 `Load()`를 호출해도 이미 로드를 시도했다면 즉시 반환하므로, Q 입력마다 파일을 새로 읽지 않습니다.

데이터가 없거나 검증 조건을 통과하지 못하면 오류 로그를 남깁니다. 검증된 데이터를 보관하지 않으며, 코드에 고정한 임의의 기본 수치로 대체하지 않습니다. 실패 후에도 같은 세션에서 자동으로 재시도하지 않으므로, 데이터를 수정한 뒤 플레이를 다시 시작하는 흐름을 설명했습니다.

### 데이터와 전투 상태의 책임

`DokkaebiGrowthDatabase`는 스킬 수치를 제공하는 클래스입니다. 현재 연계가 몇 타까지 진행됐는지와 남은 쿨타임은 `PrototypeSkillUseController`가 관리합니다. 데이터 정의와 플레이 중 변하는 상태를 같은 역할로 보지 않도록 구분했습니다.
