# 2026-08-17 개발 일지

## 오늘의 목표

- 기획 문서를 브라우저에서 빠르게 탐색할 수 있는 공개 위키로 전환합니다.
- 튜토리얼 드롭 아이템이 구현 가능한 데이터로 이어지도록 경계를 정합니다.
- 실제 Unity 구현에서 가장 먼저 검증할 플레이 단위를 결정합니다.

## 작업 내용

### 문서 위키와 탐색 구조

- MkDocs Material 설정, 문서 준비 스크립트와 GitHub Actions 배포 워크플로를 구성했습니다.
- 프로젝트 홈과 주요 폴더 인덱스에 Quick Links와 상태 표를 추가했습니다.
- 복잡한 문서 관계와 플레이 흐름은 Mermaid로 시각화하고 단순 정보에는 도표를 남발하지 않는 기준을 적용했습니다.
- GitHub Pages 게시 방식을 Actions로 설정하고 `main` 갱신 시 자동 배포되도록 만들었습니다.

### 작성자 표기 정리

- 공개 로드맵의 Revision History에 문서 정리 도구인 `Codex`가 작성자로 표시된 문제를 확인했습니다.
- 프로젝트 기획의 소유자와 결정권자는 송예찬이므로 79개 Markdown 문서의 작성자 칸을 `송예찬`으로 통일했습니다.
- 향후 작성자 칸에는 프로젝트 소유자만 기록하고 보조 도구의 사용 여부는 Git 이력이나 별도 작업 기록으로 분리하도록 문서 규칙을 추가했습니다.

### 튜토리얼 아이템 구현 가안

- 플레이어 체력 `100`, 기본 공격 피해 `10`을 초기 비교 기준으로 두는 가안을 마련했습니다.
- 코어 없이 기본 공격을 익히는 임시 무기와 코어 자원을 사용하는 첫 장비형 파츠를 분리했습니다.
- 첫 빗자루는 `쓸어치기`를 보장하고 이후 같은 원형부터 스킬·기초 능력치 무작위화를 허용하는 방향을 잡았습니다.
- 첫 코어는 `1×1`, 정기, 근접, 초기 자원 `0`, 고정 시드 능력치로 제공하는 원칙을 유지했습니다.
- 일반 드롭 확률을 직접 조작하지 않고 `TutorialOverrides`에서 필수 장비와 재료를 보장하도록 정리했습니다.
- 제안된 수치는 모두 첫 플레이 테스트를 위한 기준값이며 최종 밸런스로 확정하지 않았습니다.

### ExcelToJson 데이터 경계

- `ItemDefinitions`, `CoreDefinitions`, `SkillDefinitions`, `AffixDefinitions`, `DropTables`, `TutorialOverrides`와 소비 아이템 데이터를 독립 표로 관리하는 방향을 정했습니다.
- Excel에는 아이템 원형과 수치를 기록하고, 개별 드롭 결과인 `ItemInstance`는 런타임 생성 및 세이브 데이터로 분리합니다.
- ID 중복, 잘못된 참조, 수치 범위, 드롭 확률과 자원·스킬 호환을 변환 단계에서 검증하도록 합니다.
- Unity 오브젝트는 JSON에 직접 직렬화하지 않고 에셋 키를 ScriptableObject 카탈로그에 연결하는 혼합 방식을 사용합니다.

### 첫 Unity 구현 범위

- Unity 프로젝트에는 URP, Input Actions, 입력 경계 컴포넌트와 빈 테스트 맵이 준비되어 있음을 확인했습니다.
- 플레이어 이동·카메라·회피·상호작용은 아직 구현되지 않았습니다.
- 첫 버티컬 슬라이스를 `우클릭 지점 판정 → 장애물 우회 이동 → 아이소메트릭 카메라 추적`으로 정했습니다.
- 플레이어는 임시 Capsule로 제작하고 아트·전투·아이템 연결은 이동 검증 이후로 미룹니다.

## 발생한 문제

- 문서가 Git 저장소에는 정리되어 있었지만 브라우저에서 전체 구조와 현재 상태를 탐색하기 어려웠습니다.
- Revision History가 기획 소유자가 아니라 문서 정리 도구를 작성자로 표시하고 있었습니다.
- 튜토리얼 아이템의 종류와 역할은 정해졌지만 실제 수치, 고정 드롭과 무작위 드롭의 경계가 불명확했습니다.
- 아이템 데이터 작업과 플레이어 조작 중 무엇을 먼저 구현할지 우선순위가 필요했습니다.

## 원인

- Markdown 원문 관리에 집중해 공개 탐색과 자동 배포 흐름이 뒤늦게 추가되었습니다.
- 과거 문서 생성 과정의 작업 주체를 기획 저자와 동일하게 기록했습니다.
- 기획 규칙, 정적 밸런스 데이터와 런타임 인스턴스 데이터를 분리하지 않은 상태에서 아이템을 논의했습니다.
- 튜토리얼 전체 기능을 동시에 바라보면서 가장 짧은 플레이 가능 결과가 드러나지 않았습니다.

## 해결

- 번호 폴더의 Markdown을 단일 원본으로 유지하면서 임시 MkDocs 소스를 생성해 배포하도록 했습니다.
- 전체 Revision History의 작성자를 송예찬으로 통일하고 재발 방지 규칙을 추가했습니다.
- 문서·Excel·JSON·C#·ScriptableObject·세이브 데이터의 책임을 분리했습니다.
- 튜토리얼은 정식 데이터 구조를 사용하되 첫 획득 결과만 보정하여 학습 난이도를 일정하게 유지합니다.
- 실제 구현은 조작 가능한 테스트 공간부터 만들고 아이템 데이터는 그 위에서 즉시 검증할 수 있는 순서로 배치했습니다.

## 검증

- MkDocs 엄격 빌드를 통과했습니다.
- GitHub Actions의 Pages 배포 성공을 확인했습니다.
- 공개 사이트가 HTTP 200으로 응답함을 확인했습니다.
- 공개 로드맵에서 `송예찬`이 네 번 표시되고 `Codex` 작성자 셀이 없음을 확인했습니다.
- Unity 프로젝트에서 입력 에셋과 테스트 씬의 현재 파일 상태를 직접 확인했습니다.

## 오늘의 결과

- 기획 문서를 공개 위키에서 탐색하고 `main` 갱신마다 자동 배포할 수 있게 되었습니다.
- 문서 저자와 보조 도구의 역할이 분리되었습니다.
- 튜토리얼 아이템을 고정 학습 데이터에서 정식 무작위 파밍으로 확장할 기준이 생겼습니다.
- ExcelToJson과 Unity 에셋 연결의 책임 경계가 정리되었습니다.
- 실제 구현의 첫 완료 조건이 이동·장애물 우회·카메라 추적으로 명확해졌습니다.
