# 2026-08-18 개발 일지

## 오늘의 목표

- 캡슐 플레이어가 실제로 움직이고 카메라가 추적하는 첫 플레이 기반을 완성합니다.
- 인게임 HUD와 `Tab` 전개 화면을 Canvas 기반으로 연결합니다.
- 테스트 빗자루를 획득해 청사진에 배치하고 스킬 슬롯에 할당한 뒤 실제로 사용하는 최소 루프를 만듭니다.

## 작업 내용

### 이동과 카메라

- 우클릭 지점 이동을 구현하고 버튼을 누르고 있는 동안 커서의 월드 지점을 계속 추적하도록 입력 흐름을 조정했습니다.
- 아이소메트릭 Cinemachine 카메라가 플레이어를 추적하도록 연결했습니다.
- 지면, 장애물과 플레이어 충돌 환경을 테스트 맵에 구성했습니다.
- 플레이어 Rigidbody는 현재 이동 방식과 충돌 책임에 맞게 설정하고 중력에 의한 불필요한 낙하·기울어짐을 막았습니다.

### 정신 집중과 HUD

- 공용 회피 키 대신 `Space` 정신 집중을 현재 프로토타입 입력으로 채택했습니다.
- 누르는 동안 초당 고정량의 코어 에너지를 회복하고, 기존 에너지 바가 회복되는 것으로만 표시했습니다.
- UI Toolkit 기반 시제품 대신 Canvas/UGUI를 활성 HUD로 연결했습니다.
- 1920×1080 기준 `Canvas Scaler`, 화면 영역별 앵커, 반복 슬롯 레이아웃과 9-Slice 프레임을 적용했습니다.

### 전개 격자

- `Tab`을 누르면 필드 전체에 옅은 격자를 투영하고 현재 직군이 전개할 수 있는 영역만 청록색으로 강조하도록 구성했습니다.
- 근접 직군의 프로토타입은 동일 셀 크기의 `3×3`을 사용하고 중앙을 설계자 위치로 잠갔습니다.
- 향후 `2×2` 이상의 파츠는 셀 크기를 바꾸지 않고 여러 셀을 합친 점유 영역으로 표시하는 원칙을 정했습니다.

### 빗자루 획득과 청사진 편집

- 임시 빗자루 프리팹에 획득 데이터를 연결하고 `G` 상호작용으로 보유 파츠에 추가했습니다.
- 획득과 편집을 분리해 `G` 직후에는 창이 열리지 않고 `Tab` HUD의 `청사진 편집` 버튼으로 들어가도록 했습니다.
- 보유 파츠 선택 후 격자 좌클릭과 드래그 앤 드롭을 모두 지원했습니다.
- 배치된 파츠를 호버한 상태에서 `QWERASDF`를 눌러 스킬을 할당하고, 슬롯 직접 선택도 보조 수단으로 남겼습니다.

### 빗자루 스킬 사용

- Input Actions에 스킬 8개 입력을 연결했습니다.
- 할당 슬롯, 코어 자원과 재사용 대기를 검증한 뒤 스킬이 실행되도록 했습니다.
- 스킬 사용 중 플레이어가 커서 방향을 바라보고 잠시 이동이 제한되도록 했습니다.
- 빗자루 프리팹은 스킬 중에만 임시 손 위치에 생성됩니다.
- 내려치기·쓸어치기·찌르기를 Transform 기반 임시 모션으로 구분하고, 범위 판정으로 테스트 적에게 피해를 줄 수 있게 했습니다.
- 게임플레이 판정과 표현 계층을 분리해 이후 Animator와 Animation Event로 연출을 교체할 수 있게 했습니다.

## 발생한 문제

- 플레이어가 처음에는 우클릭을 한 번 누른 지점으로만 이동해, 누른 채 커서를 따라가는 조작감이 나오지 않았습니다.
- 기존 HUD 방식은 해상도 변화에 유연하게 대응하기 어려웠습니다.
- `G`로 빗자루를 먹자마자 편집 화면이 열리면 획득과 편성의 책임이 섞이고 플레이 흐름이 끊겼습니다.
- 에디터가 플레이 모드인 상태에서 씬 조립 빌더를 실행해 `InvalidOperationException`이 발생했습니다.
- 빗자루를 상시 손에 표시하면 다양한 장비형 파츠를 슬롯에서 조합한다는 구조와 충돌했습니다.

## 원인

- 이동 입력을 클릭 시작 이벤트로만 처리하고 버튼 유지 상태를 목적지 갱신에 사용하지 않았습니다.
- 초기 시제품은 화면 좌표 중심이었고 Canvas 앵커와 스케일 규칙이 충분히 분리되지 않았습니다.
- 획득 처리에서 편집 화면 호출까지 한 번에 수행했습니다.
- 플레이 모드 중에는 에디터 빌더가 씬 오브젝트와 에셋을 안전하게 재구성할 수 없습니다.
- 일반적인 장비 장착 방식을 그대로 적용해 스킬 파츠의 순간 현현이라는 기획 규칙을 반영하지 못했습니다.

## 해결

- 우클릭 유지 중 현재 포인터의 월드 지점을 계속 읽어 이동 목적지를 갱신했습니다.
- HUD를 Canvas/UGUI로 전환하고 기준 해상도, 앵커, 레이아웃 그룹과 9-Slice 규칙을 적용했습니다.
- `G`는 획득만 수행하고 편집은 `Tab → 청사진 편집`으로 분리했습니다.
- 플레이 모드를 종료한 뒤 빌더를 다시 실행해 씬과 프리팹 참조를 갱신했습니다.
- 스킬 시작 시 빗자루를 임시 손 위치에 만들고 모션·타격이 끝나면 제거하도록 변경했습니다.
- 판정 로직과 임시 시각 연출을 별도 컴포넌트로 분리했습니다.

## 검증

- Unity 스크립트 컴파일과 어셈블리 재로드를 통과했습니다.
- 입력 액션, 청사진 편집 UI, 임시 손 위치, 스킬 실행기와 피해 수신 컴포넌트 참조를 확인했습니다.
- `TestMap`이 플레이 모드로 진입하고 현재 콘솔에 컴파일·누락 참조·Null 오류가 없음을 확인했습니다.
- 빌더를 플레이 모드 밖에서 다시 실행했을 때 기존 오브젝트를 중복 생성하지 않고 참조가 갱신되는 것을 확인했습니다.
- 실제 전투 손맛, 세 스킬의 범위와 Animator 연계는 아직 QA 완료로 판정하지 않았습니다.

## 오늘의 결과

- 이동·카메라·HUD·전개 격자까지 이어지는 기본 플레이 화면이 구성되었습니다.
- 빗자루를 획득하고 청사진에 배치해 스킬 슬롯에 할당하는 편성 흐름이 연결되었습니다.
- 할당된 스킬이 코어 자원을 소비하고 빗자루를 순간 현현시켜 공격 판정을 만드는 최소 전투 루프가 생겼습니다.
- 현재 프로토타입에서 최종 애니메이션과 수치 튜닝을 분리해 다음 구현 단계가 명확해졌습니다.

## 다음 작업

1. 테스트 적을 배치하고 내려치기·쓸어치기·찌르기의 실제 범위와 피해를 확인합니다.
2. 캐릭터 Animator, 임시 장착 포즈와 Animation Event 타격 시점을 연결합니다.
3. 자원 부족·쿨다운·배치 실패·슬롯 덮어쓰기 피드백을 HUD에 추가합니다.
4. 빗자루 파츠 데이터를 ExcelToJson 구조와 연결하고 고정 튜토리얼 드롭을 검증합니다.
5. 코어 전개와 빗자루 스킬을 함께 요구하는 짧은 도깨비 전투 조우를 구성합니다.
