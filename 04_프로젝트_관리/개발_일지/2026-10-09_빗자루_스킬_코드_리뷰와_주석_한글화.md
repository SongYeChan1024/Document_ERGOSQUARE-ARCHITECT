## 작업 내용

### 핵심 스크립트 코드 리뷰

관련 스크립트 6개의 역할과 읽는 순서를 확인하고, 해당 위치를 편집기에서 열도록 요청했습니다. 이번 리뷰는 구조와 상태 소유 책임을 확인하는 첫 단계입니다. 전체 메서드 학습과 인게임 확인은 다음 작업으로 남깁니다.

게임 저장소의 `Assets/_ERGOSQUARE/02.Scripts`를 기준으로 다음 파일을 확인했습니다.

| 순서 | 스크립트 | 책임 |
| --- | --- | --- |
| 1 | `Gameplay/Runtime/Items/DokkaebiGrowthDatabase.cs` | JSON 로드와 조합 단계·타격 데이터 조회. 같은 파일에 성장 상태인 `DokkaebiGrowthState` 정의 |
| 2 | `Gameplay/Runtime/Items/PartDefinition.cs` | `PartInstanceData`가 개체의 고유 정보와 성장 상태 보관 |
| 3 | `Gameplay/Runtime/Items/PrototypeBlueprintLoadout.cs` | 스킬 슬롯에 도깨비 개체 연결 |
| 4 | `Gameplay/Input/GameplayInputReader.cs` | 키 입력을 슬롯 사용 요청 이벤트로 전달 |
| 5 | `Gameplay/Runtime/Combat/PrototypeSkillUseController.cs` | 자원 소비·쿨타임·연계 순서·돌진·피해 처리 |
| 6 | `Presentation/Runtime/VFX/PrototypeBroomSkillPresenter.cs` | 스킬 실행 이벤트에 맞춰 빗자루와 시각 연출 표시 |

### 상태 소유와 연계 규칙 확인

밸런스 수치를 읽는 `DokkaebiGrowthDatabase`와 현재 연계 상태를 관리하는 `PrototypeSkillUseController`의 역할을 구분했습니다. 개체의 성장 정보는 `PartInstanceData`에 연결된 `DokkaebiGrowthState`에 보관됩니다.

`PrototypeSkillUseController`의 `individualCooldowns`는 개체 ID별 쿨타임 종료 시각을 보관합니다. `chainOwner`, `nextChainStep`, `chainExpires`는 연계를 수행하는 개체, 다음 타격 순서와 다음 타격의 입력 기한을 관리합니다.

기존 규칙인 기본 공유 쿨타임 10초와 직전 타 승인부터 계산하는 연계 유예 6초를 코드에서 확인했습니다. Q1에서 공유 쿨타임을 시작하며, Q2 승인 시에는 Q3의 입력 기한만 새로 갱신합니다. 이번 작업에서 규칙·밸런스 수치와 기존 쿨타임 강화 배율은 변경하지 않았습니다.

### 영어 주석 한글화

게임 프로젝트와 자체 제작 도구의 31개 파일에서 영어 설명 주석과 파이썬 파일 설명을 한글로 정리했습니다. 스킬 실행·성장 데이터·인벤토리·이동·보스 AI·UI·빗자루 연출과 검증 도구가 포함됩니다.

- 클래스명·함수명·식별자·XML 주석 태그·실행 명령은 유지했습니다.
- 주석과 파일 설명만 바꾸고 실행 코드와 수치는 변경하지 않았습니다.
- 외부 패키지와 `tmp/SlashVerification`의 기존 변경사항은 수정하지 않았습니다.
- 새 원화·모션·맵·HUD 기능은 제작하지 않았습니다.

## 발생한 문제

영어 설명 주석과 여러 파일에 나뉜 책임 때문에 스킬 실행 흐름을 읽기 어려웠습니다. 데이터의 정의, 개체 성장 상태와 전투 중 일시적인 연계 상태를 같은 책임으로 이해하면 문제를 확인할 클래스도 혼동할 수 있습니다.

## 해결

설명 주석을 한글로 정리하고 데이터·개체 상태·키 연결·입력·전투 실행·시각 연출의 담당 클래스를 구분했습니다. `Load()`에서 데이터가 들어오는 부분부터 메서드별로 읽고, Q 입력 이후의 실행 경로로 넘어가는 학습 순서를 정했습니다.
