# 2026-09-07 개발 일지

## 오늘의 목표

- 지금까지 만든 이동·상호작용·청사진·빗자루 스킬 프로토타입을 실제 튜토리얼 순서로 연결합니다.
- 기존 테스트 맵을 훼손하지 않고 튜토리얼 전용 동굴 맵을 만듭니다.
- 플레이어의 진행 상태에 따라 목표, 차단막, 적과 완료 표식이 전환되는 최소 진행 구조를 구현합니다.
- 에디터에서 같은 튜토리얼 씬을 안전하게 반복 생성하고 검증할 수 있게 합니다.

## 작업 내용

### 튜토리얼 전용 씬과 동굴 블록아웃

- `TestMap`을 원본으로 유지하고 `Tutorial_Stage01_Awakening`을 별도 씬으로 생성했습니다.
- 플레이 시작 위치, 빗자루 획득 위치, 청사진 설정 차단막, 첫 전투 구역과 완료 지점을 한 방향 동선으로 배치했습니다.
- 바닥·암벽·통로 아치·바위 장애물과 푸른 유도등을 원시 메시와 블록아웃 머티리얼로 구성했습니다.
- 튜토리얼 전용 NavMesh 데이터를 씬 하위 폴더에 생성했습니다.
- 생성된 튜토리얼 씬을 `EditorBuildSettings`에 등록했습니다.

### 1구간 진행 상태

`TutorialStageOneController`가 다음 네 상태를 관리하도록 구성했습니다.

| 상태 | 진입 조건 | 월드 변화 | HUD 목표 |
| --- | --- | --- | --- |
| `FindBroom` | 빗자루 미보유 | 차단막 활성, 적 비활성 | 푸른 불빛을 따라가 `G`로 획득 |
| `ConfigureBlueprint` | 빗자루 보유, 스킬 미할당 | 차단막 유지 | `Tab`에서 배치 후 스킬 할당 |
| `DefeatDokkaebi` | 빗자루 배치와 스킬 할당 완료 | 차단막 해제, 적 활성 | 정신 집중과 스킬로 적 처치 |
| `Completed` | 첫 적 처치 | 적 비활성, 완료 표식 활성 | 다음 푸른 표식으로 이동 |

- 인벤토리의 빗자루 보유 이벤트와 청사진 변경 이벤트를 구독해 상태를 자동 갱신합니다.
- 적의 처치 이벤트를 받아 완료 상태로 전환합니다.
- `ITutorialObjectiveSource`로 목표 제공 경계를 정의하고 `TutorialObjectivePresenter`가 기존 HUD 텍스트에 표시하도록 분리했습니다.

### 반복 가능한 에디터 빌더

- `Tools → ERGOSQUARE → Tutorial → Build Stage 01 - Broom Awakening` 메뉴를 추가했습니다.
- 맵 블록아웃, 재료, 진행 오브젝트, HUD 참조와 NavMesh를 한 번에 구성하도록 했습니다.
- 이미 튜토리얼용으로 이름이 변경된 빗자루와 적도 다시 찾을 수 있도록 검색 조건을 보완했습니다.
- 기존 진행 제어 오브젝트를 중복 생성하거나 다른 씬으로 다시 이동하지 않도록 재실행 경계를 정리했습니다.

## 발생한 문제

- 코드 수정 뒤 Unity가 이전 에디터 어셈블리를 사용한 상태에서 빌더를 실행해 기존 이름의 `TestWeapon`을 찾지 못했습니다.
- 튜토리얼 적 처치 시 `Coroutine couldn't be started because the game object is inactive` 오류가 발생했습니다.

## 원인

- 열린 Unity Editor의 AssetDatabase가 외부에서 수정된 빌더 코드를 아직 다시 컴파일하지 않아 이전 검색 조건이 실행됐습니다.
- `PrototypeDamageReceiver.Defeated` 이벤트를 튜토리얼 진행기와 테스트 적이 함께 구독하고 있었습니다.
- 튜토리얼 진행기가 처치 이벤트에서 적을 먼저 비활성화한 뒤, 테스트 적이 같은 이벤트를 받아 비활성 GameObject에서 부활 코루틴을 시작했습니다.
- 이벤트 구독 순서가 런타임 안전 조건으로 암묵적으로 사용된 것이 직접적인 결함이었습니다.

## 해결

- Unity 에셋 새로고침과 스크립트 재컴파일을 수행한 뒤 빌더를 다시 실행했습니다.
- 빌더가 원본 이름과 튜토리얼 이름을 모두 인식하도록 수정했습니다.
- `PrototypeTrainingEnemy.OnDisable`에서 Unity가 중단한 코루틴 참조를 초기화했습니다.
- 처치 처리 시작 전과 `DefeatStarted` 이벤트 호출 뒤에 `isActiveAndEnabled`를 검사하도록 방어 코드를 추가했습니다.
- 튜토리얼 완료로 적이 비활성화됐다면 재생성 코루틴을 시작하지 않도록 했습니다.

## 검증

- 수정된 Gameplay·Content·Presentation·Editor 어셈블리 컴파일을 통과했습니다.
- 튜토리얼 씬 빌더를 연속 실행해 중복 오브젝트와 필수 참조 누락 오류가 발생하지 않는 것을 확인했습니다.
- Unity 콘솔에서 컴파일 오류와 경고가 0건임을 확인했습니다.
- 씬 YAML에서 진행 제어기, 목표 프레젠터, 빗자루 획득물, 튜토리얼 적과 블록아웃 루트 연결을 확인했습니다.
- 전용 NavMesh 에셋과 `EditorBuildSettings`의 튜토리얼 씬 등록을 확인했습니다.
- 플레이 모드에서 초기 목표가 HUD에 출력되는 것을 확인했습니다.
- 우클릭 지점 이동으로 빗자루까지 접근하고 월드 상호작용 안내가 출력되는 것을 확인했습니다.
- 자동화 입력이 Unity Input System의 실제 `G` 입력을 끝까지 재현하지 못해 전체 완료 흐름은 수동 QA 항목으로 남겼습니다.

## 오늘의 결과

- 개별 기능 시험장이던 프로토타입을 첫 번째 실제 튜토리얼 플레이 구간으로 옮길 기반이 마련됐습니다.
- 플레이어가 무엇을 해야 하는지 HUD로 안내하고, 수행 결과가 차단막과 적 활성 상태에 반영됩니다.
- 원본 테스트 맵과 튜토리얼 콘텐츠가 분리되어 이후 레벨 디자인 변경을 독립적으로 진행할 수 있습니다.
- 에디터 빌더를 다시 실행해도 같은 씬을 복원할 수 있어 반복 테스트 비용이 줄었습니다.
- 적 비활성화와 부활 처리의 이벤트 순서 의존성을 제거했습니다.

## 다음 작업

1. 키보드와 마우스로 1구간 전체 플레이 경로를 수동 QA합니다.
2. 다음 튜토리얼 구간에 `1×1` 정기 코어 배치와 자원 자동 생성을 구현합니다.
3. 정신 집중과 코어 자원 생성량을 HUD 및 실제 스킬 소비와 연결합니다.
4. 빗자루 도깨비의 추적·공격·어그로 상태 머신을 구현합니다.
5. 전투 구역의 폭, 조우 거리, 카메라 시야와 장애물 배치를 플레이테스트로 조정합니다.
