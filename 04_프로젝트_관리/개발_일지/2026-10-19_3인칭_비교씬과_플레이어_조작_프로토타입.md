## 오늘의 목표

3인칭 카메라와 직접 이동으로 바꿀 가능성을 검토하고, 기존 데모를 유지한 별도 씬에서 같은 캐릭터·전투·스퀘어 구성을 시험할 수 있게 만듭니다. 오늘의 결과는 본편 조작 방식의 최종 전환이 아닌 비교용 구현입니다.

## 작업 내용

### 1. 조작안과 스킬 슬롯 정리

WASD를 이동에 사용하면 기존 W·A·S·D 스킬키와 충돌합니다. 사용자가 제안한 QERTZXCV를 스킬 8칸에 배정하고 F는 상호작용, 1234는 소모품으로 분리했습니다. 내부 슬롯 번호는 유지하고 비교 전용 Input Actions 자산에서 물리 키를 바꿨습니다. 기존 새 UI의 버튼·배지·키 배정도 비교 씬의 키에 맞췄습니다.

| 입력 | 비교 씬 용도 |
| --- | --- |
| WASD·마우스 이동 | 카메라 기준 이동·시점 회전 |
| 좌클릭 | 보존된 원래 3단 기본 공격 |
| Q E R T Z X C V | 스킬 8칸 |
| F | 상호작용·시험 보급대 |
| 1 2 3 4 | 소모품 4칸 |
| Shift·Space | 비교용 달리기·기존 정신 집중 |
| B/Tab·Esc | 새 장비/스퀘어 UI·메뉴 닫기 또는 커서 해제 |

### 2. 별도 연습장과 플레이어 연결

`Assets/_ERGOSQUARE/01.Scenes/Comparison/ThirdPerson_Comparison.unity`에 연속 지면·거리선·표적 3개·카메라 장애물·F 보급대를 배치했습니다. 기존 독립 `Player_Architect_Demo.prefab`의 씬 인스턴스에 비교용 입력·카메라·피드백을 추가했으며, 원본 프리팹을 교체하지 않았습니다.

기존 이동기의 선택 기능으로 카메라 기준 직접 이동을 사용하고 대각선 속도를 정규화했습니다. 이동 시 캐릭터는 이동 방향, 공격·스킬 요청 시에는 카메라의 수평 방향을 향합니다. 기존 FSM·Animator·공격 데이터·이동 잠금을 재사용하며, 루트 `Demo Player Rig`에서 재생 전 연결을 확인할 수 있습니다. 카메라는 구체 캐스트로 벽 앞에서 거리를 줄입니다.

### 3. 실제 전투와 시험용 지급 구성

검은 장착된 상태로 시작합니다. 기본 공격은 원래 3타와 기존 피해 판정을 사용하고, 실제 검 끝 잔상과 스킬 방향 가이드·표적 체력을 표시했습니다. 시각 효과가 별도 피해를 만들지는 않습니다.

비교용 Lv.5에서 최초 3×3에 Q 빗자루와 코어, 성장 선택으로 만든 두 번째 2×3에 E 월도와 독립 코어를 미리 구성했습니다. 이는 두 스킬을 독립 냉각으로 비교하기 위한 연습장 설정입니다. 나머지 스킬 6칸은 비어 있고 기존 새 UI에서 재배정할 수 있습니다. 기존 튜토리얼의 최초 지급·성장 규칙은 유지합니다.

### 4. 소모품·보급·메뉴 입력

1번에는 회복약, 2번에는 정기약을 각 3개 지급했습니다. 회복량 +30과 공통 재사용 대기 2초는 가안이며 3·4번은 빈 예약 슬롯입니다. 이미 가득 찬 상태에서는 약품을 소모하지 않습니다.

F 보급은 체력·정기·약품·표적 체력을 회복하며 스킬 냉각은 유지합니다. 메뉴에서는 커서를 풀고 이동·공격·스킬·소모품 입력을 차단합니다. 메뉴 밖 커서 해제 상태에서도 전투 입력이 발생하지 않게 했습니다. 비교 지급과 약품 상태는 이 씬의 메모리에만 유지하고 기존 튜토리얼 세션 인계·영구 저장에 기록하지 않습니다.

## 발생한 문제

- WASD와 기존 8칸 스킬의 물리 키가 충돌했습니다.
- 기존 플레이어 루트가 Agent의 높이 오프셋을 포함해 카메라·시험 배치를 단순 지면 기준으로 맞추면 위치가 어긋났습니다.
- NavMesh 경계의 지면 좌표를 루트 이동에 그대로 사용하면 높이가 내려갈 수 있었습니다.
- Q와 E가 같은 코어에 연결되면 한 스킬의 냉각이 다른 스킬의 비교를 제한했습니다.

## 원인

기존 입력과 이동은 쿼터뷰 클릭 이동을 전제로 했으며, 플레이어 루트와 지면 기준점의 높이가 달랐습니다. 코어 냉각 공유는 기존 설계대로 동작했지만 두 스킬의 조작감을 번갈아 시험하기에는 별도 구성이 필요했습니다.

## 해결

별도 입력 자산과 씬별 UI 키 재정의를 사용했습니다. 카메라는 실제 상체 기준으로 맞추고 시험 배치는 Agent 오프셋을 포함했으며, 경계 이동은 수평 성분으로 제한했습니다. 연습장에만 두 공간과 독립 코어를 미리 구성했습니다. 기존 데모의 입력·플레이어·맵 자산과 빌드 씬 목록은 보존하고, 공통 코드의 직접 이동·UI 키 재정의는 명시적으로 선택하는 기능으로 추가했습니다.

## 검증

별도 Unity 6000.3.7f1에서 Input System 키보드·마우스 이벤트와 실제 FSM·Animator·피해 처리를 사용했습니다. 다음 수치는 최종 검수 결과이며 중간 실패·수정 검사를 합산하지 않습니다.

| 검수 영역 | 결과 | 근거 |
| --- | --- | --- |
| 편집 모드 연결·키 바인딩 | 11개 통과 | `edit-checks.txt` |
| 비교 씬 실제 플레이 기능 | 45개 통과 | `verification.json`, `checks.txt` |
| 원래 데모 클릭 이동·Animator·전투 | 210개 통과 | `legacy-animator-verification.json` |
| 기존 자산 보존 | 85개 해시 동일 | `preservation-verification.json` |
| 전달 파일 | 30개 기록 | `delivered-files.json` |

3단 연계의 타격 3회·총 피해 45, 빗자루 실제 피해와 월도 실행, 자원·냉각, 소모품·F 보급·메뉴 차단, 벽 앞 이동·루트 높이·카메라 거리 축소를 확인했습니다. 원래 데모 회귀에는 반복 프레임 검사가 포함됩니다. 검사 중 프로젝트 런타임 오류는 없었습니다.

기준 폴더는 Unity 저장소 `Tools/ArtReview/ThirdPerson_Comparison_20261019`입니다. 별도 자동 기능 검사와 화면 기록이며, 사용자의 메인 Unity에서 조작감을 직접 평가하거나 전체 튜토리얼을 수동 완주한 결과는 아닙니다.
