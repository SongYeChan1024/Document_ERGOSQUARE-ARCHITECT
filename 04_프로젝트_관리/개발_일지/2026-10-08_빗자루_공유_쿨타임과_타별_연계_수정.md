## 오늘의 목표

빗자루가 조합으로 1·2·3타까지 확장되는 하나의 스킬이라는 전제에 맞춰, 공유 쿨타임과 다음 타 대기 시간을 분리합니다. 코드·엑셀·JSON·기획 명세를 같은 타이밍 규칙으로 맞춥니다.

## 작업 내용

### 1. 최종 연계 규칙

| 항목 | 적용 규칙 |
| --- | --- |
| 기본 쿨타임 | 1·2·3자루 모두 공통 10초. Q1 승인부터 계산 |
| Q1 → Q2 | Q1 승인부터 6초 동안 다음 타 대기 |
| Q2 → Q3 | 3단계에서 Q2 승인부터 새로 6초 동안 다음 타 대기 |
| Q2·Q3 쿨타임 | 별도 쿨타임 없음. Q1에서 시작한 쿨타임을 다시 시작하지 않음 |
| 연계 종료 | 마지막 해금 타격 승인 또는 다음 타 대기 만료 |
| 새 Q1 | 연계가 종료되고 남은 공유 쿨타임도 끝나야 승인. 실행 중 모션의 회복은 유지 |
| 실패·선입력 | 실패 입력·예약·명중·모션 종료로 대기 제한을 갱신하지 않음 |

QQQ는 설명용 입력이며 실제로는 할당한 동일 스킬 키를 사용합니다. 기존 HASTE 강화 배율은 기본 10초에 적용하며 피해·비용·모션·돌진·성장 보존 규칙은 변경하지 않았습니다.

강화가 없는 기본값의 시간 예시입니다.

| 입력 | 연계 대기 | 쿨타임 | 결과 |
| --- | --- | --- | --- |
| 0초 Q1 후 입력 없음 | 6초에 종료 | 10초에 종료 | 6초에 Q1 대기로 복귀, 4초 남음 |
| 0초 Q1, 5초 Q2 후 입력 없음 | Q3 대기는 11초에 종료 | 10초에 종료 | 10초에도 Q3 대기 유지, 11초에 새 Q1 가능 |
| 0초 Q1, 5초 Q2, 10.5초 Q3 | 마지막 타 승인으로 종료 | 이미 종료 | Q3 회복 후 새 Q1 가능 |

오늘 중간에 적용했던 전체 연계 고정 6초 제한은 최종 규칙이 아닙니다. Q2 승인부터 Q3 대기를 다시 6초로 갱신하는 규칙으로 대체했습니다. 10월 7일 일지의 4.5/5.5/6.5초·연계 1.2초는 당시 수치 이력으로 유지합니다.

### 2. 상태와 실행 코드

- `PrototypeSkillUseController`의 `individualCooldowns`는 고유 개체 ID별 쿨타임 종료 시각을 소유합니다. Q1 승인에서만 설정합니다.
- `chainOwner`, `nextChainStep`, `chainExpires`는 현재 연계 개체·다음 순서·다음 타 대기 기한을 소유합니다.
- `TryStartBroomChain`은 조건과 자원 소비를 통과한 타격 승인 시 대기 기한을 갱신합니다. 마지막 해금 타격이면 연계를 종료하되 쿨타임은 유지합니다.
- `ExpirePendingChain`은 입력이 없어도 기한 만료를 처리합니다. `Update`와 상태 조회·승인 경로에서 만료 상태를 확인합니다.
- `Execute` 종료에서 다음 순서를 열되 대기 기한을 모션 종료 시각으로 미루지 않습니다. 선입력은 기존 마지막 0.18초의 입력 한 건만 예약합니다.
- 같은 개체의 키 재할당, 실패 입력, 컨트롤러 비활성화로 남은 쿨타임을 초기화하지 않습니다.

### 3. 데이터와 문서 동기화

- [밸런스 엑셀](../../01_게임_기획/05_밸런스/outputs/2026-10-08_도깨비_조합/도깨비_스킬_밸런스.xlsx)의 Stages 기본 쿨타임을 모두 10초로 변경했습니다. `comboWindow=6`은 직전 타 승인부터 다음 타를 기다리는 시간입니다.
- 기존 엑셀을 다시 생성하지 않고 6개 셀의 값·설명만 변경했습니다. 시트·서식·행 높이·열 너비·고정 창·입력 검증의 유지 여부를 비교했습니다.
- `DokkaebiGrowth.json`을 엑셀에서 재생성하고 최초 엑셀 생성 도구의 초기값·레이블도 맞췄습니다.
- [종합 기획서](../../00_프로젝트_개요/에르고스퀘어_종합_기획서_초안.md), [조합 성장 명세](../../01_게임_기획/01_핵심_플레이/장비_코어_스킬/도깨비_조합_성장_명세.md), 게임 데이터 편집 안내를 보완했습니다.
- 오늘은 새 원화·맵·스킬 모션을 제작하지 않았습니다. 기존 화면을 새 결과처럼 첨부하지 않습니다.

## 발생한 문제

Q1부터 전체 연계를 고정 6초로 제한하면 Q2를 늦게 사용했을 때 Q3 입력 기회가 짧아집니다. 단계별 쿨타임도 조합으로 진화하는 하나의 스킬이라는 최종 요구와 달랐습니다. 쿨타임이 끝난 시각과 연계가 끝나는 시각을 같은 상태로 취급하면, 유효한 Q3 대기 중 새 Q1으로 건너뛸 수 있습니다.

## 원인

공유 재사용 제한과 다음 타 입력 제한은 서로 다른 시계인데, 이전 명세는 전체 연계 제한을 Q1에 고정했습니다. 엑셀 초기값은 조합 단계별로 쿨타임이 달랐습니다.

## 해결

공유 쿨타임은 Q1에서 한 번만 시작하고, 다음 타 기한은 직전 타 승인에서만 갱신하도록 분리했습니다. Q1 대기 복귀와 재사용 가능을 구분하고, 모든 단계의 기본값을 10초로 통일했습니다. 쿨타임 종료 이후에도 연계 기한이 남아 있으면 다음 순서를 유지합니다.

## 검증

| 검증 | 결과 | 확인 범위 |
| --- | --- | --- |
| Unity 네이티브 Play 성장 시험 | 104항목 통과 | 공통 10초, Q1 단독 만료 후 약 4초 잔여, 늦은 Q2의 새 6초, 쿨타임 종료 중 Q3 유지, 늦은 Q3 후 새 Q1, 실패·자동 만료 및 기존 성장 회귀 |
| 엑셀 변환 단위시험 | 13개 통과 | 마감 시 재실행. 잘못된 입력·참조·수식·출력 보존 등 |
| Excel ↔ 생성 JSON 일치 | 통과 | 마감 시 `Export-Growth.ps1 -Check` 재실행 |
| 엑셀 변경 범위·서식 비교 | 통과 | 의도한 6개 셀만 변경, 전체 시트의 기존 서식·고정 창·크기·입력 검증 유지 |
| 원본 튜토리얼 씬 SHA256 | 동일 | 1구간·보스 구간 씬 두 개를 수정하지 않음 |

게임 저장소의 `Tools/Verification/DokkaebiGrowthSmokeTest.cs`와 `DokkaebiGrowth_v3.result.json`에 최종 검증을 보존합니다. 중간 고정 6초 규칙의 80항목 결과는 `DokkaebiGrowth_v2.result.json`에 과거 이력으로 보존하며 현재 사양의 근거로 사용하지 않습니다.

검증은 별도 Unity 복제본의 그래픽 없는 Play 모드에서 진행했습니다. Unity Search 인덱스 초기화 예외는 있었지만 게임 코드 컴파일 오류 없이 시험을 완료했습니다. 실제 화면·사용자 조작감·독립 실행 빌드는 이번 자동 시험의 범위가 아닙니다.
