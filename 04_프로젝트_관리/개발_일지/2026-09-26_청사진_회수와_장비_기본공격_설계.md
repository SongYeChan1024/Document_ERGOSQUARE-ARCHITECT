# 2026-09-26 새벽 개발 일지

작성자: 송예찬 · 프로젝트: ERGOSQUARE: ARCHITECT  
작업일·기록일: 2026-09-26 (한국 시간, 새벽 작업)

## 오늘의 목표

청사진을 회수하고 이동 후 재전개할 수 있도록 만들고, 현재 프로토타입을 튜토리얼 이야기로 연결합니다. 플레이 피드백을 통해 첫 전투의 대기 시간을 줄일 후속 개발 방향을 정합니다.

## 작업 내용

### 1. 청사진 수동·자동 회수 — 구현

- Tab HUD에 청사진 회수 버튼을 연결했습니다.
- 설치 시점의 설계자 격자 중심을 고정 원점으로 삼아 수평 거리 12m 초과 시 자동 회수합니다. 높이 차이는 제외합니다.
- HUD에 현재 거리와 한계를 표시하고 한계의 80%부터 주황색으로 경고합니다.
- 12m는 임시값입니다. Unity의 `PrototypeBroomPlacementPresenter > Automatic Recall Distance`에서 조정합니다.
- 회수 시 코어·빗자루의 필드 설치 표시와 테두리를 제거하고 코어 자동 생성을 중지합니다.
- 보유 파츠, 청사진 편성, 스킬 배정, 현재 자원, 코어 내구도는 유지합니다.
- 코어 연결을 먼저 해제하고 실물을 비활성화해 회수가 파괴로 처리되지 않게 했습니다. 재전개 시 같은 코어를 재사용하여 무료 수리도 방지합니다.
- 실제로 파괴된 코어는 회수로 복구되지 않습니다.
- 회수 후 전개 화면을 닫고 요청 입력을 비워 같은 클릭이 재설치로 이어지지 않도록 했습니다.
- 코어 자동 회복 학습 도중 회수한 경우 재전개를 안내합니다.

### 2. 튜토리얼 시나리오·연출 — 검토안 작성

기존 상세 연출 문서 상단에 R-00~10 검토안을 추가했습니다. 파일을 새로 분산하지 않고 기존 후보는 참고 영역으로 보존했습니다.

기상 → 기억 흔적 → 빗자루와 첫 관계 → 편집·스킬 학습 → 첫 전투 → 코어 전개·회수 → 토벌팀 조사 → 초가집·월도 → 영혼 해방·복귀 흐름입니다.

각 구간에 시작 조건, 플레이어 행동, 대사 가안, 시각 연출, 길 안내, 완료 판정, 막힘 처리를 작성했습니다. SFX와 음성은 준비된 것으로 간주하지 않고 텍스트·조명·오브젝트 움직임부터 제안했습니다.

원안의 첫 전투 후 장비 획득과 현재 프로토타입의 빗자루 선획득이 다르므로, 동행 빗자루와 첫 전투 적을 다른 개체로 두는 안을 승인 전으로 표시했습니다. 필수 기억 흔적 축소, 주머니·플레이트의 도입 시점과 보스 구현 범위도 미결정으로 남겼습니다.

문서는 앱 오른쪽 패널에서 열도록 요청했습니다. 이 단계는 시나리오 구현 완료가 아닙니다.

### 3. 첫 전투 피드백 — 후속 설계

사용자는 첫 전투에서 에너지를 회복하며 싸우는 시간이 너무 길다고 피드백했습니다. 스킬을 쓰기 위해 정신집중 대기를 반복하는 구조를 기본 공격으로 보완하기로 방향을 잡았습니다.

| 구분 | 장비창 | 청사진 |
| --- | --- | --- |
| 의미 | 설계자가 직접 착용하는 물건 | 파츠·재료를 배치·전개하는 공간 |
| 초기 범위 | 기본 무기 슬롯 1개 | 기존 코어·스킬 파츠 편성 |
| 전투 역할 | 자원 없는 좌클릭 기본 공격 | QWERASDF 스킬과 코어 자원 생성 |
| 향후 확장 | 착용 방어구 등 | 보조 파츠·주머니·방어 플레이트 등 |

청사진을 인벤토리화한 것이 장비창까지 대체한다는 뜻은 아니라는 점을 명확히 했습니다. 대원의 무기를 G로 획득하고 장비 슬롯에 장착하는 흐름을 후속 구현 대상으로 논의했습니다. 무기의 종류·능력치·공격 수치는 미정입니다.

사용자는 Tab 화면 안에 청사진 탭과 장비 탭을 따로 두는 방식을 제안했습니다.

- 청사진 탭: 격자·전개 미리보기, 편집 버튼, 회수 버튼.
- 장비 탭: 착용 슬롯·보유 장비 선택·장착 정보.
- 입력 제안: 평상시 좌클릭은 공격, 전개 화면 좌클릭은 설치, 편집·장비창에서는 UI 조작만 수행.
- 탭 전환 자체는 필드 설치물을 자동 회수하지 않는 방향.
- 여분 장비의 청사진 보관, 교체 시 빈 공간 부족 처리, 첫 진입 탭과 전투 중 장비 교체 조건은 세부 검토가 필요합니다.

**장비 슬롯·기본 공격·장비 탭은 아직 구현하지 않았습니다.** 시나리오 검토안도 이 논의보다 먼저 작성했으므로, 다음 작업에서 대원 무기 획득과 기본 공격 학습 순서를 반영해야 합니다.

## 발생한 문제와 원인

1. 전개한 청사진을 이동 후 재사용하는 회수 경로가 필요했습니다.
2. 코어를 단순 삭제하면 파괴 처리로 오인하거나 새 인스턴스 생성 시 내구도가 회복될 수 있습니다.
3. 전체 시나리오의 순서와 현재 프로토타입의 보상·학습 순서가 다릅니다.
4. 첫 전투가 스킬 자원 회복에 의존해 사용자가 긴 대기 시간을 체감했습니다.
5. 장비형 파츠와 캐릭터의 직접 착용 장비를 동일한 범주로 취급하면 기본 공격과 빌드의 역할이 혼동됩니다.

## 해결 및 남은 경계

- 수동·자동 회수를 공통 경로로 처리하고 코어의 연결 해제와 파괴를 분리했습니다.
- 비활성 코어 재사용으로 내구도를 보존했습니다.
- 현재 구현, 연출 제안, 원안 변경이 필요한 결정을 문서에서 구분했습니다.
- 직접 착용 장비와 청사진을 분리하고, 기본 무기 슬롯 하나부터 검증하는 방향으로 정리했습니다.
- 코어 파괴·철수·수리, 실제 적 공격 AI, 보스 전장의 회수 악용 가능성은 여전히 후속 과제입니다.
