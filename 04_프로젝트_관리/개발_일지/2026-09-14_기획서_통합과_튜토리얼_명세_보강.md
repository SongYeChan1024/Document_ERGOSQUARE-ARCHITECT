# 2026-09-14 개발 일지

작성자: 송예찬 · 프로젝트: ERGOSQUARE: ARCHITECT

## 오늘의 목표

분산된 기획서의 기준을 하나로 정리하고, 튜토리얼을 구현할 때 필요한 조건·데이터·예외·수용 시험을 보강합니다.

## 작업 내용

### 상세 명세 작성 기준 보강

- [위키독스 상세 기획서 템플릿](https://wikidocs.net/371390#1)을 참고해 프로젝트에 필요한 기록 항목을 정리했습니다.
- 기능 ID, 실행 조건, 상태 전환, 데이터 원본, 실패·취소, UI·연출과 수용 시험을 연결하도록 했습니다.
- 튜토리얼 첫 구간의 네 상태 `FindBroom → ConfigureBlueprint → DefeatDokkaebi → Completed`와 실제 판정 조건을 기록했습니다.
- 기획 합의, 코드 구현, 플레이 검증 상태를 구분하고 전체 연속 플레이를 통과로 표시하지 않았습니다.

### 종합 기획서와 부록 통합

- 종합 기획서를 게임 규칙·세계관 전체 이야기·튜토리얼의 단일 기준으로 전환했습니다.
- 개별 시스템 문서 12개를 하나의 시스템 상세 부록으로 모았습니다.
- 중복 개요·시나리오 8개는 종합 기획서로 통합하고 관련 링크를 변경했습니다.
- 세계관 전체 이야기를 본문에 넣으면서 용어를 누르면 설명으로 이동하는 구조를 유지했습니다.
- 데이터·문화권별 파츠·원화·기술 자료는 독립 편집 가능한 부록으로 유지했습니다.
- 통합 전 20개 파일의 전체 원문과 SHA256을 단일 아카이브에 보존했습니다. 원문 포함 여부를 확인한 뒤 기존 개별 파일을 제거했습니다.
- README, 운영 규칙, AI 작업 컨텍스트, 웹 메뉴와 문서 상호 링크를 수정했습니다.

## 발생한 문제

- 개별 문서들이 각각 기준을 주장해 동일한 기능에 여러 사양이 공존했습니다.
- 코어 전개 시 자원 0 시작, 모든 직군 중앙 칸 예약, F 전개 등 과거 규칙이 남아 있었습니다.
- 전투 중 스킬 할당 해제 시 진행 단계가 되돌아가 적이 비활성화되는 현재 동작이 확인 과제로 남았습니다.
- 통합 중 Windows 줄바꿈 처리로 표 행이 벌어졌고 일부 상대 경로와 한국어 제목 앵커가 웹에서 맞지 않았습니다.

## 원인

규칙 변경 때 모든 문서가 함께 갱신되지 않았고, 기획 목표와 프로토타입 동작·검증 결과의 경계가 불명확했습니다. 문서 이동 시 상대 경로와 웹 렌더러의 제목 ID 생성 규칙도 함께 고려해야 했습니다.

## 해결

- 게임 규칙은 종합 기획서가 우선하도록 운영 기준을 변경했습니다. 부록의 미확정 후보는 자동 승인하지 않습니다.
- 코어 전개 시 기존 자원을 유지하며 중앙 원점 예약은 근접 튜토리얼 기준으로 한정했습니다.
- F는 스킬 슬롯으로 유지하고 전개 확정 입력, Q/E 회전 충돌, 감속과 기록 개수 등은 DEC-01~08 검토 항목으로 분리했습니다.
- 현재 첫 구간과 정식 TUT-00~08 전체 기획의 구현 범위를 분리했습니다.
- 아카이브에서 표 행을 복원하고 상대 경로를 수정했습니다. 용어집과 한국 원화 개체에는 명시적 앵커를 추가했습니다.
- 이후에도 재실행할 수 있는 링크·앵커 검사 스크립트를 남겼습니다.

위 수치는 일지 추가 전 통합 산출물 검증 기준입니다. 이번 작업에서는 Unity 코드를 수정하거나 새 플레이테스트를 수행하지 않았습니다. 첫 구간의 전체 플레이, 실제 코어·주머니 방어, 월도 보스와 폐쇄·복귀는 완료로 간주하지 않습니다.
