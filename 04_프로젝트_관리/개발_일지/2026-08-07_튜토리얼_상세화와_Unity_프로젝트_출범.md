# 2026-08-07 개발 일지

## 오늘의 목표

- 도깨비 잠복 게이트 튜토리얼을 실제 구현에 착수할 수 있는 세부 명세로 분해합니다.
- 기획 문서와 실제 게임 소스의 책임을 분리하고 Unity 개발 저장소를 출범합니다.
- Codex에서 문서와 Unity 프로젝트를 함께 다루되 Git 작업의 기본 대상을 명확히 합니다.
- 초기 프로토타입에 맞는 Git 브랜치·작업트리·Unity 폴더 구조를 결정합니다.

## 작업 내용

### 튜토리얼 세부 기획

- TUT-00 기상부터 TUT-08 게이트 폐쇄와 현실 복귀까지 장면·목표·연출·트리거·예외 처리를 상세화했습니다.
- 기억 투영형 도깨비, 영혼 주입형 도깨비와 `사람을 죽인 도깨비 — 월도`의 역할과 최소 전투 패턴을 분리했습니다.
- 토벌팀 5인의 기록·장비, 일반 드롭, 보호 퀘스트 아이템과 월도 보상 체계를 작성했습니다.
- 수납 모듈 파괴 중에도 폐쇄 인증과 영혼 결박 파편이 소실되지 않는 진행 보장 규칙을 두었습니다.
- 레벨 A~G를 실제 그레이박스가 가능한 공간 요구와 체크포인트 단위로 구체화했습니다.
- 구현 시스템, 리소스, 개발 순서와 테스트 체크리스트가 새 상세 명세를 참조하도록 연결했습니다.

### 실제 게임 저장소 출범

- GitHub에 비공개 저장소 [`ERGOSQUARE-ARCHITECT`](https://github.com/SongYeChan1024/ERGOSQUARE-ARCHITECT)를 만들었습니다.
- 로컬 경로 `C:\GitHubProjects\ERGOSQUARE-ARCHITECT`에 Unity `6000.3.7f1` 프로젝트를 생성했습니다.
- `main` 브랜치와 첫 커밋 `8911e12 chore: initialize Unity project`를 원격 저장소에 푸시했습니다.
- Unity의 `Assets`, `Packages`, `ProjectSettings`를 추적하고 `Library`, `Temp`, `Logs`, `UserSettings`와 IDE 생성 파일을 제외했습니다.
- 프로젝트 README에 첫 프로토타입 범위와 문서 저장소 링크를 기록했습니다.

### Codex 프로젝트 연결

- Unity 저장소를 Codex 로컬 프로젝트의 기본 폴더로 전환했습니다.
- `Document_ERGOSQUARE-ARCHITECT`는 보조 폴더로 유지해 기획과 구현을 한 작업에서 교차 확인할 수 있게 했습니다.
- 새 작업의 기본 Git·작업트리·PR 대상은 Unity 저장소가 되며, 문서 저장소는 별도 Git 이력을 유지합니다.
- 기존 대화는 시작 당시 문서 저장소의 작업 경로를 유지하므로 저장소별 명시적 경로를 사용합니다.

### Git과 작업트리 운영 결정

- 초기에는 영구 작업트리를 만들지 않고 한 기능 브랜치씩 개발해 `main`에 통합합니다.
- `main`은 언제든 Unity에서 열 수 있는 안정 상태로 유지합니다.
- 첫 구현 브랜치는 `codex/tutorial-foundation`을 후보로 두었습니다.
- 장기간 병렬 실험이 생겼을 때만 영구 작업트리를 사용합니다.
- Unity 작업트리마다 `Library`가 별도로 생성되어 디스크와 임포트 시간이 증가한다는 점을 운영 조건으로 기록했습니다.

### Unity 프로젝트 구조 결정

```text
Assets/_ERGOSQUARE/
├─ Core/          부트스트랩·이벤트·저장·공통 유틸리티
├─ Gameplay/      플레이어·전투·AI·에르고스퀘어·아이템·게이트
├─ Content/       개별 게이트와 튜토리얼 콘텐츠
├─ Presentation/  카메라·UI·VFX·오디오
├─ Editor/        프로젝트 전용 에디터 도구
└─ Tests/         EditMode·PlayMode 테스트
```

- 외부 에셋은 `Assets/ThirdParty`로 분리합니다.
- 공용 시스템과 `Content/Tutorial_Dokkaebi`의 전용 몬스터·레벨·기록을 분리합니다.
- 최초 씬은 `Bootstrap`, `CombatSandbox`, `Tutorial_Dokkaebi` 세 개를 기준으로 합니다.

## 발생한 문제

- 튜토리얼의 시나리오·레벨·아이템·적 정보가 여러 문서에 흩어져 실제 구현 단위를 판단하기 어려웠습니다.
- 문서 저장소만으로는 Unity 생성 파일과 소스 코드 이력을 안전하게 관리하기 어려웠습니다.
- 문서와 Unity 저장소를 동시에 연결하면 어느 저장소가 Git 작업의 기본 대상인지 혼동될 수 있었습니다.
- Unity 프로젝트에서 영구 작업트리를 무분별하게 만들면 작업트리마다 대형 `Library` 캐시가 생길 수 있었습니다.

## 원인

- 기존 문서는 세계관과 플레이 흐름을 설명하는 수준이었고 트리거·드롭·AI·체크포인트의 구현 계약이 부족했습니다.
- 기획 산출물과 실행 가능한 게임 프로젝트의 수명 주기 및 추적 대상이 서로 다릅니다.
- Codex의 다중 폴더 프로젝트에서는 기본 폴더가 Git·작업트리·PR의 기준이 됩니다.

## 해결

- 상세 플롯, 아이템·드롭, 몬스터·보스를 독립 명세로 만들고 상위 문서는 링크와 책임만 유지했습니다.
- 문서와 실제 게임을 두 GitHub 저장소로 분리하고 README로 상호 연결했습니다.
- Unity 저장소를 기본 폴더, 문서 저장소를 보조 폴더로 정했습니다.
- 초기 개발은 단일 로컬 체크아웃과 짧은 기능 브랜치로 진행하고 영구 작업트리는 필요가 생긴 뒤 도입하기로 했습니다.
- Unity 코드는 범용 시스템과 튜토리얼 전용 콘텐츠를 분리하는 기능 중심 구조를 사용하기로 했습니다.

## 검증

- Unity `6000.3.7f1` 배치 모드에서 프로젝트 생성과 재실행이 정상 종료되었습니다.
- Unity 생성 폴더가 Git 추적 목록에 포함되지 않았음을 확인했습니다.
- Unity 저장소의 로컬 `main`과 `origin/main`이 동일한 커밋을 가리키고 작업 트리가 깨끗함을 확인했습니다.
- 튜토리얼 문서의 상대 링크와 필수 섹션을 검사했습니다.
- 문서 변경은 `git diff --check`를 통과했습니다.
