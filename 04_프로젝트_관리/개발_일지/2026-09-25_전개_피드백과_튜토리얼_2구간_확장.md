# 2026-09-25 개발 일지

작성자: 송예찬 · 프로젝트: ERGOSQUARE: ARCHITECT  
작업일: 2026-09-25 · 기록 작성일: 2026-09-26

## 오늘의 목표

청사진의 실제 설치 여부를 시각적으로 구분하고, 첫 몬스터 처치 후 막혀 있던 튜토리얼을 코어 학습 구간까지 확장합니다.

## 작업 내용

### 1. SFX 없는 전개 피드백

- 반투명 미리보기와 실제 설치 인스턴스를 구분했습니다.
- 설치 인스턴스 생성 후에만 `청사진 전개 완료` 알림을 표시합니다.
- 설치 셀 외곽선을 0.6초 동안 한 번 점멸시키고 알림은 2.5초 유지합니다. 수치는 프로토타입 조정값입니다.
- Tab을 닫아도 설치물·외곽선과 `전개 중` 상태를 유지합니다.
- 범위 밖·중앙 칸·장애물 충돌 등의 실패 이유를 안내합니다.
- 편집창은 `청사진에 편성했습니다(필드 미전개)`로 표현해 편성과 실제 설치를 구분했습니다.
- Canvas와 해상도 스케일러로 상태·알림을 표시하며, UI 클릭이 필드 전개로 처리되지 않도록 보완했습니다.

### 2. 코어 획득과 전개 학습

사용자가 첫 몬스터를 처치하고 기존 푸른 표식까지 이동한 것을 확인했습니다. 기존 진행기는 표식 활성화까지만 처리했으므로 다음 구간을 연결했습니다.

1. 첫 적 처치 후 푸른 표식의 수평 반경 3m 안으로 이동합니다.
2. 앞쪽에서 G로 `낡은 정기의 혼 코어`를 획득합니다. 편집창은 자동으로 열리지 않습니다.
3. Tab → 청사진 편집에서 코어와 빗자루를 서로 다른 칸에 편성합니다.
4. 편집 종료 후 필드를 좌클릭해 두 파츠를 전개합니다.
5. 코어의 실제 자동 회복량이 5 이상 누적되면 두 번째 훈련 적이 활성화됩니다. 자원이 가득 찬 경우 먼저 스킬로 소비하도록 안내합니다.
6. 두 번째 적을 처치하고 끝 표식에 도착하면 현재 프로토타입의 종료 지점임을 안내합니다.

코어 카드는 클릭과 드래그 편성을 지원합니다. 코어는 1×1이고 중앙 칸을 사용할 수 없으며 QWERASDF 스킬 슬롯을 차지하지 않습니다. 두 파츠 모두 지면·충돌 판정을 통과해야 실제로 전개합니다.

### 3. 자원 규칙과 확정 범위

- Space는 정신집중을 유지합니다. 코어마다 고유 행동을 주는 아이디어는 이번에 적용하지 않았습니다.
- 정신집중은 전개 전후 모두 사용할 수 있으며 코어와 동일한 정기 풀을 회복합니다.
- 전개 시 기존 정기는 초기화하지 않습니다.
- 코어는 정기·근접·1×1의 고정 보상입니다. 랜덤 직군·능력치 드롭은 제외했습니다.
- 정상 코어의 초당 회복량 20, 기존 자원 풀 최대 100은 튜토리얼 시험 기준입니다.
- 남은 코어 내구도 비율에 따라 생성 효율이 감소하고 파괴 시 자원 사용을 차단하는 기초 처리를 연결했습니다. 실제로 코어를 공격하는 적 AI와 복구 시설은 아직 없습니다.

### 4. 동굴 통로와 전투 공간 확장

| 위치 | 역할 |
| --- | --- |
| Z=-21 | 기존 바닥 시작점 유지 |
| Z=18 | 기존 첫 구간 완료 표식·후속 진입 |
| Z=24 | 코어 획득 지점 |
| Z=30~36 | 전개 연습 공간 |
| Z=39 | 두 번째 훈련형 도깨비 |
| Z=49 | 두 번째 구간 종료 표식 |
| Z=53 | 확장된 끝 벽 |

끝 벽 이동, 바닥·좌우 벽 연장, 안내 조명과 가장자리 바위를 추가했습니다. 지형뿐 아니라 NavMesh도 다시 생성하고 플레이어를 유효한 표면에 재배치합니다.

원본 씬의 첫 구간 배치와 기존 작업을 보존하기 위해 **확장 공간은 Play 시작 시 런타임 블록아웃으로 조립**합니다. 편집 모드에서 완성된 2구간 지형이 저장되어 있는 방식은 아닙니다. 기존 씬에는 코어 데이터 참조를 연결하고, 씬 빌더에서도 해당 참조를 유지하도록 보완했습니다.

## 발생한 문제

- 설치 뒤 전개 화면만 닫혀 성공 여부를 알아보기 어려웠습니다.
- 첫 전투 후 푸른 표식은 안내용이었고 도착 판정·다음 단계가 없었습니다.
- 기존 종단 벽과 바닥·이동 데이터가 첫 구간까지만 구성되어 있었습니다.
- 청사진 편집 UI와 보관함이 빗자루 하나에 맞춰져 있어 코어를 별도로 편성할 수 없었습니다.
- 검증용 무화면 Unity에서 재생 시간이 진행되지 않았고, 에디터 검색 인덱서 예외도 발생했습니다.

## 원인

첫 프로토타입은 빗자루 획득·스킬 할당·첫 처치까지 검증하는 범위였습니다. 실제 설치 상태를 보여 주는 표현 계층과 다음 학습 구간, 복수 파츠 UI가 별도로 필요했습니다. 자동 시험에서는 화면 없는 에디터의 프레임 진행 조건도 고려해야 했습니다.

## 해결

- 실제 설치 성공 이후에만 시각 피드백을 보내고 편집·미리보기 상태와 분리했습니다.
- 첫 구간 진행기에 후속 구간 진행기를 연결했습니다. 코어 자원 생성 상태는 Gameplay에 두고 튜토리얼은 학습 순서만 관리합니다.
- 기존 보관함과 청사진 데이터에 코어를 추가하고, 두 파츠 전개 표현을 별도 프레젠터로 분리했습니다.
- 맵 연장과 NavMesh 재생성을 함께 수행해 보이는 길과 이동 가능한 길을 맞췄습니다.
- 별도 복제 프로젝트에서 프레임 스텝을 사용해 자동 진행 시험을 완료했습니다. 사용자 작업 중인 Unity 프로젝트를 시험용으로 전환하지 않았습니다.
